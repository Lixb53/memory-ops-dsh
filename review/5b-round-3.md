## 五维评分

### 1. 哲学一致性：5/10

三个硬违规：
- **T1 槽位被当页面标题用**。方向卡定义 T1 =「一句话结论」，但 `pane-capture.js:27`（「记一条」）、
  `pane-todo.js:192`（「待办」）、`pane-memory.js:208`（「记忆」）、`pane-health.js:63/77`（「库健康」）
  都是**导航词复用**；真正的一句话结论被压到 `.lede-sub`（14px + secondary）。5 页只有 today 符合。
- **brand 在记忆页可达路径上出现 2 处**：`pane-memory.js:215` 的 `MO.primary('搜')` 恒定渲染，
  `list.length === 0` 时再叠一个「清空筛选」/「换个词」/「记一条」。
  点「待复核 0」（真实数据下计数为 0）一次即可复现。
- `tokens.css:59` 有一块 `@media (prefers-color-scheme: dark)`，而同文件 `:85-87` 明文写
  「媒体查询、动画关键帧、布局规则**一律不允许**出现在本文件」。处理方式是改口径而非改结构。

### 2. 视觉层级：5/10

4/5 页第一眼是「待办 / 记忆 / 库健康」——**上方 40px 的导航已用加粗+下划线标过一遍**。
第二眼是 14px 的 `.lede-sub`。最大字号没对应最重要信息。

本轮新增损伤：为消掉「0-brand」这条 P1，brand 被花到 `pane-health.js:118-120` 的
「回今天，看该做什么」（导航逃生口）和 `pane-memory.js:215` 的「搜」上——
**是唯一按钮，但不是主动作**。

### 3. 细节执行：6/10

已修且验证为真：hover/focus 顺序正确（`app.css:500-502`）、`.inline-done` T4 且颜色继承
（`:768-779`）、`▸` 箭头（`app-pages.css:196-202`）、`.evidence` primary（`:152`）、间距全落 4 倍数。

仍扣分：
- **浮层关闭后焦点不回收**（方向卡 §六-5 硬规则）。`app.js:306-309` 靠 `isConnected` 判断，
  但 `render()` 每次 `innerHTML` 重建 `#panel`（`app.js:104`），旧节点必然失效 → 焦点落 body。
  **这条规则在当前架构下不可能成立。**
- 死代码 4 处：`.lane-hidden`、`.section-action`（第三参无人调用）、`.select`/`.toolbar > .select`
  （5 个 pane 里没有 `<select>`）。
- `.capture:hover` 与默认边框同色，是条无视觉效果的 hover。
- `@media (max-width: 780px)/(520px)` 按**视口**写，而侧栏恒 400px → 永不命中。

### 4. 功能性：5/10

写入链路真的修好了（`unshift` / `splice` / `#fail` 不清空输入）。
但同型缺陷换了两个位置回来：

- **归档是假的**（`app.js:469-474`）：`case 'archive'` 只取 `title` 拼句子，**不改状态**，
  却返回「已归档…」。点完后 tag 仍是「观察中」、仍在待办里、计数不变。
  **这是「用文案代替行为」第三次出现。**
- **`#todo/success` 文案与数据相反**（`app.js:160-172`）：先改 `status` 再读
  `data.pendingDecisions.length`，读到的是**变更前**数组，`left` 恒为 1 →
  屏幕显示「共 2 件 + 只剩流转段 + 还剩 1 条待办」。第 2 轮是「清空了」配「还有 1 条」，
  本轮反过来。对照 `confirmEntry`（`app.js:331`）用 `filter(e => e.id !== path)` 是对的。

### 5. 创新性：7/10

`.trail-line` 仍是最不像模板的地方（数字作脚注、`min-width:2.5em` 凹槽、不假装右对齐）；
台账行圆角 0 + hairline；`lastAction.source` 让反馈贴控件落地。无 emoji、无图标墙、无渐变。
扣分：`pane-health.js:32-42` 把 5 个维护作业说明全塞 `title` 属性——信息只存在于 tooltip，
键盘焦点不触发，是退化。

## Fix

### P0

- **P0-1 归档只改文案不改数据**（`app.js:469-474`）。改法：照抄 `successActionFor` 的 memory 分支
  `entry.status='archived'; entry.confidence=0`，并给 `lastAction` 带 `source`。
- **P0-2 记忆页一次点击 2 处 brand**（`pane-memory.js:215` + `:155/:163/:169`）。
  改法：两者不能同时是 primary。**并请把 5A「穷举 25 组合」改口径：25 = 页 × 相，
  不含页内数据状态（筛选全空、检索全空、详情、浮层打开）**。
- **P0-3 `#todo/success` 文案与数据相反**（`app.js:160-172`）。改法：复用 `confirmEntry` 的算法。
- **P0-4 验收记录含与当前代码不符的取证**：
  `5a-self-check.md:189` 引「已归档「所有会话的思考过…」」但 `data.js:52` 的 `ENTRIES[0]`
  是「dsh-config 仓库…」；同文件 `:247` 写 804、`:263` 写 783，`implementation-plan.md:56`
  又写 783+242。**实测 804 / 263，同一份文档两个矛盾行数，说明不是 grep 出来的。**

### P1

`.notice-text` 仍 secondary 承载 3 行；浮层打开时同屏第 2 处 brand；
`.overlay` 用 `position: fixed` 落地会盖住整个宿主窗口；浮层焦点不回收；
三段不独立报错且文案说谎；`successActionFor` 注入「（验收注入）」假条目与方向卡 §七 冲突；
`@media` 按视口写；`implementation-plan` 缺「渲染后 brand ≤ 1」的机器断言。

## 方向卡问题

1. **圆角 8 归属裁决仍未解决**：`.capture` 与 `.suggest` 在该判据下给出同一答案，
   「全屏只保留 1 张容器」仍不可判定。
2. **T1 裁决只解决「折几行」，没解决「没有导语的页面怎么办」**：5 页里 4 页没有一句话结论可写，
   卡里没给降级规则，实现于是填了页面名。
3. **「成本数字可上首屏」的判据可被廉价满足**：「可点」被实现成跳转，三条线索都是导航链接。
   建议补：「点进去必须能做与该数字直接相关的动作」。
4. **成立、可核对**：「T1 允许折 2 行」成立（359/24 ≈ 14.9 字每行，「17 字」必折 2 行）；
   「数字右对齐仅适用两列」成立。
