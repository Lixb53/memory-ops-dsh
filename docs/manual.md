## 负三、初始化：从零建起一个能用的库

> **这一节只对「库是空的」的人有用。**
> 如果你打开总览已经能看到几十篇记忆，说明库早就建好了，跳过本节，直接看 §负一。
> 判断依据：总览 → 预算账本里 L2「详情层 · 文件数」是不是 0。

### 先搞清楚：哪些要手动，哪些自动

这一步必须先说清，否则很容易白折腾——**大部分东西是自动的**。

| 东西 | 会不会自动建 | 说明 |
|---|---|---|
| `~/.memory-ops/` 根目录 | ✅ 自动 | 插件加载时就建好 |
| `.state/`（事件流、未命中） | ✅ 自动 | 同上 |
| `personal/`、`work/`、`archive/` | ✅ 自动 | 只是空目录 |
| `personal/INBOX.md` | ✅ 自动 | **第一次「记一条」时**自动生成，不用手建 |
| `personal/` 其他档案（身份/原则…） | ❌ 手动 | 不建也能用，只是个人档案区是空的 |
| `work/<项目>/index.md` | ❌ 手动 | **不建则「本项目」永远认不出项目** |
| 记忆条目（`work/<项目>/*.md`） | ❌ 手动 | 靠捕获或 agent 写 |

**结论**：真正必须手做的只有一件事——**建项目索引**。其余可选。

> 为什么 INBOX 要等第一次捕获才生成：设计上不让空库预先铺满空文件，
> 否则「空文件」和「真的没有记录」在界面上长得一样。

---

### 第 1 步 · 确认库在哪、是不是空的

打开 DSH → 左侧栏 **记忆库** → **总览**。

看两处：

1. **预算账本**里的 L2「详情层 · 文件数」：`0` 就是空库。
2. 跑一次 healthCheck（见 §零），返回里的 `root` 就是库的实际位置：

| 系统 | 默认位置 |
|---|---|
| macOS | `/Users/<你的用户名>/.memory-ops` |
| Windows | `C:\Users\<你的用户名>\.memory-ops` |

> 如果你设过环境变量 `MEMORY_OPS_ROOT`，以它为准——
> 界面上显示的数字和 `root` 一致，才说明你看的是同一个库。

**这一步不需要你做任何操作，只是确认。** 目录不存在也没关系，下一步会建。

---

### 第 2 步 · 记第一条（这一步会自动建好 INBOX）

左侧栏 **记忆库** → **记录流** 页签 → 顶部那个常驻的输入框，打一句话，回车。

比如：「今天开始用记忆库，先记一条测试」。

成功后你会看到：

- 记录流里出现一行：`| 日期 | 想法 | 今天开始用… | open | — |`
- 磁盘上自动出现 `personal/INBOX.md`

**为什么先做这一步**：它同时验证了「插件能写」「库路径对」「INBOX 骨架正确」三件事，
是最省事的第一次冒烟测试。比先手写文件靠谱得多。

> 如果这里报错，先停下排查，别继续往下——后面所有步骤都依赖写链路是通的。

---

### 第 3 步 · 建项目索引（唯一必须手动的一步）

**不建这一步，「本项目」页签永远是空的**，而且会顶着一条降级条说「没认出项目」。

> **为什么不能自动建**：目录能自动建（工作域捕获会顺带创建
> `work/<项目>/INBOX.md`），但**项目身份**必须由 `index.md` 声明。
> 系统只把 `work/<项目>/index.md` 当作「这个项目存在」的证据——
> 只有 INBOX 的目录不算项目（实测：`projectAliasesOf` 返回空，
> 识别报「库里还没有任何项目」）。
>
> 原因是不想让"随便往某个目录写过一句话"就凭空造出一个项目。
> 但这也意味着初始化时你必须显式声明一次。

#### 先拿到项目名

项目名 = **git remote 的仓库名**。这是唯一决定项。

**关键理解**：这里有两样东西容易混——

| 对象 | 由谁决定 | 自由吗 |
|---|---|---|
| 你的代码放在哪个目录（会话 cwd） | 你自己 | ✅ **完全自由**，目录叫什么都不影响识别 |
| 记忆库里的 `work/<项目名>/` 这个文件夹名 | **git remote 名** | ❌ 必须与 remote 一致 |

也就是说：`C:\work\zhongxing\V2.1.25-dev` 这种名字里根本不含项目名的目录，
照样能被正确识别成 `sz-web`——只要那个仓库的 remote 是 `sz-web`。
**目录名不参与判断，remote 参与。**

**macOS**

```bash
cd /你的/项目/路径
git remote get-url origin
# 输出形如 git@github.com:Lixb53/memory-ops-dsh.git
#                                  ↑ 这一段就是项目名
```

**Windows（PowerShell）**

```powershell
cd G:\你的\项目\路径
git remote get-url origin
# git@github.com:Lixb53/memory-ops-dsh.git → 项目名 memory-ops-dsh
```

去掉 `.git` 后缀、取最后一段，就是项目名。`https://` 和 `git@` 两种 remote 写法都支持。

> **为什么要 remote 而不是目录名**：remote 是仓库的固有身份——
> 目录改名、换盘、开多个分支副本，它都不变。早期版本靠 `aliases` 手工登记
> 「哪些目录名属于我」，漏登记就变空态，**该字段已废弃（2026-11），写了不生效**。
>
> **实测确认**（`resolveScope`）：
> - cwd = `C:\work\zhongxing\V2.1.25-dev`，remote = `sz-web` → 识别为 `sz-web` ✅
> - cwd = `C:\other\renamed-folder`，remote = `sz-web` → 识别为 `sz-web` ✅
> - 同一 cwd 但读不到 remote → 退回路径匹配，识别失败 ❌
>
> 所以：**项目文件夹名必须等于 remote 名，你的代码目录名随便。**

#### 建索引文件

在库的 `work/` 下建一个以项目名命名的目录，里面放 `index.md`。

**macOS**

```bash
# 把 memory-ops-dsh 换成你第 1 步拿到的项目名
mkdir -p ~/.memory-ops/work/memory-ops-dsh
cat > ~/.memory-ops/work/memory-ops-dsh/index.md <<'EOF'
---
id: work.memory-ops-dsh.index
title: memory-ops-dsh 索引
scope: work/memory-ops-dsh
kind: fact
layer: l1
status: active
pinned: false
tags: []
---

# memory-ops-dsh

## 我能查什么

- 架构结论 → `_shared/`
- 踩过的坑 → 本篇同级目录

## 该读哪个文件

（有具体记忆后在这里写路径表，让 agent 知道去哪找）
EOF
```

**Windows（PowerShell）**

> ⚠️ **这里有个必须避开的坑**：PowerShell 5.1 的 `Set-Content -Encoding UTF8`
> **会写入 BOM**（文件开头多 3 个不可见字节 `EF BB BF`）。
> BOM 会让 frontmatter 彻底失效——`---` 前面多了字节，解析器认不出，
> 结果是 `layer` 变成 `—`、标题退化成文件名、整篇被当成无元数据的普通文件。
> **而且它不报错**，你只会觉得「怎么填了不生效」。
>
> 所以下面用 `[System.IO.File]::WriteAllText` + 无 BOM 编码器。

```powershell
$proj = 'memory-ops-dsh'          # 换成你的项目名
$dir  = Join-Path $env:USERPROFILE ".memory-ops\work\$proj"
New-Item -ItemType Directory -Path $dir -Force | Out-Null

$content = @"
---
id: work.$proj.index
title: $proj 索引
scope: work/$proj
kind: fact
layer: l1
status: active
pinned: false
tags: []
---

# $proj

## 我能查什么

- 架构结论 → ``_shared/``
- 踩过的坑 → 本篇同级目录

## 该读哪个文件

（有具体记忆后在这里写路径表，让 agent 知道去哪找）
"@

# 关键：$false = 不写 BOM
[System.IO.File]::WriteAllText((Join-Path $dir 'index.md'), $content, [System.Text.UTF8Encoding]::new($false))
```

> **frontmatter 必须写全**。缺 `id` / `scope` 会让这篇在界面里显示异常。
> `layer: l1` 表示它是索引层——只在被 read 时付费，不是常驻前缀。
>
> **验证 BOM 是否写对了**（前 3 个字节应该是 `45,45,45`，即 `---`）：
> ```powershell
> $b = [System.IO.File]::ReadAllBytes((Join-Path $dir 'index.md'))
> $b[0..2] -join ','     # 45,45,45 = 无 BOM ✓   239,187,191 = 有 BOM ✗
> ```
> 已经写坏了也不要紧，用上面的 `WriteAllText` 重写一遍即可覆盖。

#### 验证

回到 **本项目** 页签。判定标准：

| 看到 | 意思 |
|---|---|
| 没有降级条 + 「本项目还没有记忆」 | ✅ 认知成功，只是还没记东西 |
| 有琥珀色降级条 | ❌ 项目名和 remote 不一致，看降级条里写的「原因」，照它改 |
| 有降级条且写「库里还没有任何项目」 | ❌ `index.md` 没建对，检查路径和文件名 |

降级条本身是好设计：**它宁可说「我不确定」，也不假装「这个项目没有记忆」**。

### 第 4 步 · 建个人档案（可选，但建议做）

个人档案是「agent 认识你」的地方。不建也能用，只是个人区一直空着。

建议至少建两个文件——**身份**和**原则**：

**macOS**

```bash
mkdir -p ~/.memory-ops/personal
cat > ~/.memory-ops/personal/identity.md <<'EOF'
---
id: personal.identity
title: 身份
scope: personal
kind: fact
layer: l2
status: active
pinned: false
tags: []
---

# 身份

- 我是谁：
- 我做什么：
EOF

cat > ~/.memory-ops/personal/principles.md <<'EOF'
---
id: personal.principles
title: 原则
scope: personal
kind: fact
layer: l2
status: active
pinned: false
tags: []
---

# 原则

- （你定的规矩写这里，agent 会照着它做事）
EOF
```

**Windows（PowerShell）**

> 同样要用无 BOM 写法，`Set-Content -Encoding UTF8` 会加 BOM（见第 3 步的说明）。

```powershell
$p = Join-Path $env:USERPROFILE '.memory-ops\personal'
New-Item -ItemType Directory -Path $p -Force | Out-Null
$utf8 = [System.Text.UTF8Encoding]::new($false)   # $false = 不写 BOM

$identity = @"
---
id: personal.identity
title: 身份
scope: personal
kind: fact
layer: l2
status: active
pinned: false
tags: []
---

# 身份

- 我是谁：
- 我做什么：
"@
[System.IO.File]::WriteAllText((Join-Path $p 'identity.md'), $identity, $utf8)

$principles = @"
---
id: personal.principles
title: 原则
scope: personal
kind: fact
layer: l2
status: active
pinned: false
tags: []
---

# 原则

- （你定的规矩写这里，agent 会照着它做事）
"@
[System.IO.File]::WriteAllText((Join-Path $p 'principles.md'), $principles, $utf8)
```

> **Windows 编码坑（两条都要避）**：
> 1. 别用默认编码——中文会变乱码
> 2. 也别直接用 `-Encoding UTF8`——它会加 BOM，让 frontmatter 失效
>
> 用上面的 `[System.Text.UTF8Encoding]::new($false)` 才对。
> macOS 的 `cat` heredoc 这两个问题都没有。

这两个文件不用一次写全，可以随时改——它们是普通 Markdown，你说得越具体，agent 越懂你。

### 第 5 步 · 让 agent 真的用起来（这步才决定它有没有价值）

前面四步只是把库建起来。**库建好不等于 agent 会用**。

在一个真实会话里，问一个**你确实踩过坑**的技术问题。然后看两件事：

1. agent 有没有调 `memory_recall`
2. 调了之后有没有命中

**第一次几乎必然不命中**——因为库是空的。这不是失败，这正是「未命中」页签存在的意义：
它记录下「你反复问、但库里没有」的问题，告诉你该补什么。

补的方式：**未命中** 页签 → 找到那条 → 写结论 → 确认落库。

---

### 第 6 步 · 确认初始化成功

回到 **总览**，对照这张表：

| 检查项 | 期望 |
|---|---|
| L2 详情层 · 文件数 | ≥ 2（INBOX + 个人档案各 1；项目索引算 L1，不在此列） |
| L1 索引层 · 文件数 | ≥ 1（你刚建的项目索引） |
| 待你处理 | 0（新库没有推断积压） |
| 命中率 / 确认率 | `—`（分母为 0，**不是 0%**） |
| 域统计 | 能看到 `personal` 和你的项目名 |
| 本项目页签 | 无降级条 |

> **`—` 与 `0%` 是两件事**：`—` 表示「还没发生过，算不出来」，
> `0%` 才表示「发生了但全落空」。别把算不出来当成算出来是零。

到这里库就建好了。接下来看 §负一，开始真正用它。

---

### 初始化常见卡点

| 症状 | 原因 | 怎么办 |
|---|---|---|
| 总览一片 0，L2 也是 0 | 库是空的，还没捕获过 | 做第 2 步 |
| 「本项目」有降级条 | 项目目录名 ≠ git remote 名 | 改成一致（第 3 步） |
| 降级条说「库里还没有任何项目」 | `work/<项目>/index.md` 不存在或路径不对 | 检查是不是建成了 `work/index.md` |
| 中文全变乱码 | Windows 用了默认编码写文件 | 用 `[System.Text.UTF8Encoding]::new($false)` 重写 |
| **frontmatter 看着对但不生效**（`layer` 是 `—`、标题变成文件名） | **文件带 BOM** | 用无 BOM 写法重写；查前 3 字节是不是 `45,45,45` |
| 文件建好了但界面看不到 | 界面缓存 | 刷新页面 |
| 手改文件后状态不对 | 缺 frontmatter 必填字段 | 照模板补全 `id`/`scope`/`kind`/`layer`/`status` |

## 负一、第一次用，从哪开始（照着做就行）

> **前提：库已经建好了**（见 §负三）。如果你打开总览是空的，先去做初始化。

> 记忆库不是「装好就自动帮你」的工具，它的设计假设是**人负责拍板、agent 负责取用**。
> 所以「开始使用」= 先把这四件事做一遍，之后它才会开始真的帮你。

### 第 1 步：确认它在读你的库（10 秒）

看「总览」页签顶部：**待你处理**应该有个非零数字，**域统计**里应该能看到 `sz-web 35 篇`。
如果是 0 篇，先跳到 §八 排查，别急着改数据。

### 第 2 步：清掉「待你处理」（今天的 5 分钟）

进「总览 → 待你处理」，把那 2 条推断逐条**确认**或**驳回**。
这一步不能跳过，原因很实际：**未处理完的推断会一直占着队列**，
而「确认率」这个指标在它们处理完之前没有意义。

### 第 3 步：让 agent 知道该读什么（这才是重点）

记忆库的读者主要是 agent，而 agent 取用靠三样东西：

| 东西 | 在哪 | 作用 |
|---|---|---|
| `memory_recall` 工具 | 模型自己调 | 按关键词检索，命中记 `cite`，未命中记 `miss` |
| 项目索引 `work/<项目>/index.md` | 库内 | 告诉 agent「哪类问题该读哪个目录」 |
| 项目目录名 | `work/<名>/` 的目录名 | 让「本项目」认出项目——**须等于 git remote 仓库名**（见 §二） |

所以「开始使用」的那一刻，就是**你在一个真实会话里问一个你踩过坑的问题**，
然后看 agent 有没有调 `memory_recall` 命中它。命中了，这套机制就转起来了。

### 第 4 步：跑一周后再看三个数

一周内**真的提问几次**，再回来看「总览」：

| 指标 | 健康值 | 不健康说明什么 |
|---|---|---|
| 命中率 | > 60% | 分母在涨、分子为 0 → agent 搜到但没用上，或库里的东西不相关 |
| 确认率 | > 70% | 推断太多没人拍板 → 回第 2 步 |
| 未命中「该补了」 | 越少越好 | 这些是**你自己反复问到、但库里没有**的问题，最该补 |

> **一开始命中率很可能是「—」而不是 0%**：`—` 表示分母为 0（还没检索过），
> 和「检索过但全落空」是两件事。别把算不出来当成算出来是零。

### 别做的三件事

| 别做 | 为什么 |
|---|---|
| 把整个库喂给 agent | 那会毁掉「常驻前缀 361 tokens」这个第一指标，退化成第二个知识库 |
| 手动批量改 `status` | 状态流转有唯一合法路径，绕过它会打乱三率口径 |
| 指望它自动往里写结论 | 设计上只产出草稿。**人确认才落库**，这是它敢被信任的前提 |

---

## 负二、怎么装（只装一次）

装完才有下面所有的界面。**两条路线都对，按你的场景选。**

本文所有命令都分 **macOS** 与 **Windows** 两栏。**别跨系统抄命令**——
路径分隔符、shell 语法、代理变量写法都不一样，抄错会得到看起来像「插件坏了」、
其实只是命令不对的症状。

---

### 路线 A：从 GitHub 直接装（推荐）

适合「换台机器 / 只想用、不改代码」。

#### A-1 · 先让代理生效（这台机器不配代理必失败）

DSH 安装时拉的是 `codeload.github.com`。直连会报：

```
os error 10054  或  远程主机强迫关闭了一个现有的连接
```

**必须在启动 DSH 的那个终端里**设好代理变量，再从同一个终端启动。端口改成你自己代理软件里的。

**macOS（zsh / bash）**

```bash
# 临时的：只对当前这个终端窗口生效
export HTTPS_PROXY='http://127.0.0.1:7897'
export HTTP_PROXY='http://127.0.0.1:7897'

# 想长期生效，写进 shell 配置（选你用的那个）
echo "export HTTPS_PROXY='http://127.0.0.1:7897'" >> ~/.zshrc
echo "export HTTP_PROXY='http://127.0.0.1:7897'"  >> ~/.zshrc
source ~/.zshrc
```

**Windows（PowerShell）**

```powershell
# 临时的：只对当前这个 PowerShell 窗口生效
$env:HTTPS_PROXY = 'http://127.0.0.1:7897'
$env:HTTP_PROXY  = 'http://127.0.0.1:7897'

# 想长期生效，写进用户环境变量（新开的窗口才生效）
[Environment]::SetEnvironmentVariable('HTTPS_PROXY', 'http://127.0.0.1:7897', 'User')
[Environment]::SetEnvironmentVariable('HTTP_PROXY',  'http://127.0.0.1:7897', 'User')
```

> **两个系统的同一个坑**：只配「系统代理」都**不够**，git 不读系统设置，只读环境变量。
> 浏览器能打开 GitHub 会让人误以为网络没问题，实际上 git 和 pnpm 仍在直连。
>
> **Windows 额外注意**：`$env:` 只在当前窗口有效；用 `SetEnvironmentVariable` 写的值，

> 端口不对会得到 `connection refused`，看起来像「插件没装」，其实只是敲错了地方。

## 二、最常见的困惑：「本项目」显示 0 条

这一节**改写过两次**，因为上一版把 bug 写成了「设计如此」。

### 先说结论：0 条有两种完全不同的原因

| 画面 | 真正的原因 | 该怎么办 |
|---|---|---|
| 0 条 + 顶部**没有**降级条 | 这个项目**确实**还没有记忆 | 去「记忆」页签看全库，或给它记一条 |
| 0 条 + 顶部**有琥珀色降级条** | 没认出当前是哪个项目 | 看降级条写的「原因」，按 §二 核对项目名是否等于 git remote 名 |

**降级条是真话，空列表不是。** 只要它出现，就说明系统**不确定**这个项目是谁——
此时它退回「全部记忆」，而不是假装「这个项目没有」。

### 「本项目」判定项目的方式

**已经换了三代实现**，当前是第三代。了解顺序能少走弯路：

```
① git remote（最优先）——仓库固有身份，改名也不失效
   ↓ 没命中（不是 git 仓库 / 仓库名与项目名不同）
② 路径匹配：cwd 里任一段 == 项目名 → 精确命中
   ↓
③ 前缀匹配：某段以「项目名 + - _ .」开头 → 前缀命中
   ↓ 都失败
④ 报降级条，退回「全部记忆」
```

关键点：

1. **你的代码目录叫什么完全不影响判定**——`V2.1.25-dev`、`renamed-folder` 都能
   正确认成 `sz-web`，只要那个仓库的 remote 是 `sz-web`。这点常被误解成「目录名要对上」。
2. 唯一要对上的是**库里那个文件夹名**：`work/<项目名>/` 必须等于 git remote 名（去掉 `.git`）。
   因为 remote 读出来是 `sz-web`，系统就去库里找 `work/sz-web/`，找不到就算认不出。
3. 不是 git 仓库（或读不到 remote）才会走 ②③ 的路径匹配；那是兜底，不是主路径。
   所以**先在 `work/` 建好同名目录，比调整代码目录名有用得多**。
4. 目录名前导的点会被忽略：`.dsh` 能匹到项目 `dsh`
5. 同分时**更具体的赢**：项目名精确命中 > 前缀命中

> **`aliases` 已废弃（2026-11）**。老版本靠在 `work/<项目>/index.md` 里写
> `aliases: [分支名, 子模块名]` 来登记「哪些目录属于我」。
> 现在**字段保留解析但完全不读**——写了也不生效，不报错。
>
> 为什么废弃：它在承担两个已经独立的职责。分支归属改由目录结构派生，
> 仓库身份改由 `git remote` 判定（比目录名可靠，改名也不失效）。
> 于是它只剩「给未建项目的子模块目录起别名」这一个用途，
> 而那本该**给子模块单独建一个项目目录**来解决——这也更符合「子模块记忆独立」。

**所以新项目的初始化动作是**：

```
work/<项目名>/index.md 建起来，项目名取 git remote 的仓库名
```

如果子模块要有自己的记忆，就再建 `work/<子模块名>/index.md`，
不要把它塞进主项目的别名表——那样它永远会被解析成主项目。

## 二·五、捕获为什么不按当前项目自动归位（一个已知缺口）

这一节回答一个很自然会问的问题：**我人在某个项目里，为什么记的东西全进了个人域？**

### 现状：确实是全进个人域

右侧栏「快速捕获」、记录流顶部输入框、`/remember`——**这三个入口都写死个人域**。
实测代码：`stream.ts` 与 `remember.ts` 里都是 `domain: 'personal'` 硬编码，
不读当前会话的 cwd。

所以：

| 你以为 | 实际 |
|---|---|
| 在 memory-ops-dsh 项目里记一条 → 进该项目 | ❌ 进 `personal/INBOX.md` |
| 「本项目」页签能看到刚记的 | ❌ 看不到（它在个人域） |
| 只有个人域有记录流 | ✅ 就是这个现状 |

### 底层其实是支持按项目分的

`store.appendInbox({ domain: 'work/<项目>' })` 会写到 `work/<项目>/INBOX.md`，
目录和文件都会自动建。实测这一条通：

```
capture({ content: '…', domain: 'work/memory-ops-dsh' })
→ work/memory-ops-dsh/INBOX.md  ✅ 自动创建
```

**但界面三个入口没有把当前项目传下去。** 这是接线缺口，不是设计如此。

### 为什么这件事没被自动化（我的判断）

有两个真实的技术障碍，不是「忘了做」：

1. **项目身份要有落点**：捕获到工作域前，得先知道「这是哪个项目」。
   而项目身份由 `work/<项目>/index.md` 声明——文件还不存在时，
   系统无法从 remote 名反推出「该建哪个项目」。顺序上有先有鸡先有蛋。
2. **记错地方的代价不对称**：进个人域只是「多了一条要归档的」；
   进错项目域会污染那个项目的记忆，而且**人很难发现**。

所以现在的取舍是：**先保证不写错，宁可都放个人域**。

### 那么现在怎么把内容归到项目

三条路，按从易到难：

1. **手动编辑**：直接改 `~/.memory-ops/personal/INBOX.md`，把行剪切到
   `work/<项目>/INBOX.md`。格式就是同一张五列表，粘过去即可。
2. **让 agent 写**：在会话里让 agent 用 `memory_write`（`mode: entry`）落到
   `work/<项目>/...`，它带 cwd 上下文，能算对项目。
3. **直接建条目**：在 `work/<项目>/` 下按模板新建 `.md`，frontmatter 里
   `scope: work/<项目>`。

> 这是本手册里**唯一一处「能力有、界面没接」**的地方，和 `product.md` §2.3
> 记录的那类缺口同源。要不要补，见该节的取舍讨论。

## 三、日常怎么用：三个高频动作

### 动作一：随手记一条（最常用）

**入口**：右侧栏 →「快速捕获」，或输入框打 `/remember`

1. 选类型（想法 / 计划 / 问题 / 待办 / 决策）
2. 写一句话（**贴多行会自动拆分逐条存**）
3. `⌘ + Enter` 提交（或点「记一条」）

存进去的是**记录流**（`~/.memory-ops/personal/INBOX.md` 的一行），不是档案。
存完 30 秒内可以点「撤销」。

> **隐私闸门**：内容里出现密钥、私钥、身份证、内网 IP 会被**拒写**，
> 并给你一段脱敏后的文本，点「填入脱敏文本」可以改完再存。

### 动作二：处理待办（每周一次就够）

**入口**：侧栏「记忆库」→ **总览** 页签 → 「待你处理」区

这里放的是**需要你拍板**的条目：推断待确认的、到期该退役的。

每条有这些按钮：

| 按钮 | 什么时候点 | 点了以后 |
|---|---|---|
| **确认** | 这条是对的，留下来 | 就地变「已确认」，置信度 0.9 |
| **驳回…** | 这条不对 | 跳到详情页，**那里**有理由输入框（理由必填） |
| 看详情 | 想看全文和证据链 | 打开详情 |
| 再留 90 天 | 还有用，但现在没空处理 | 到期计时重置 |

> **点了没反应？** 现在不会了。每个按钮点完，队列上方都会出现一条结果条：
> 成功是绿色「确认」，失败是红色并**带出宿主的原始错误**（例如
> `确认失败：非法状态迁移：hypothesis → confirmed`）。
> 早先这里是完全静默的：失败连一句提示都没有，所以「确认无效」看起来像功能坏了。

> **驳回为什么必须写理由**：驳回后 30 天内它不再参与纠错。
> 30 天后回看时，没有理由就说不清当初为什么否掉，只能原样恢复——那这机制就白转一圈。

> **驳回为什么在总览里点了要跳页**：总览是「一眼一批」的列表，塞个输入框会把节奏打断；
> 详情页才放得下理由框。所以总览的按钮标了省略号「驳回**…**」——它表示「还有下一步」。

你当前库里有 **2 条**待拍板。

#### 为什么「确认」过去必然失败（已修）

状态机有两张表，之前用错了一张：

| 表 | 回答的问题 | hypothesis → confirmed |
|---|---|---|
| 自动爬升表 | 「系统能不能自己把它升上去」 | ❌ 不许跳级 |
| **人拍板表** | 「人看完说它对，能不能留」 | ✅ 允许 |

UI 的确认按钮走的是 `setStatus`，而它当时用自动表校验。
待处理队列里最常见的就是 hypothesis（推断待确认），于是**每次都报非法迁移**。
这等于「确认按钮在设计上永远不该能用」——已改为人表校验。

### 动作三：检索（让「命中率」有意义）

**入口**：侧栏「记忆库」→ **记忆** 页签 → 顶部搜索框

输入关键词，**按回车**（或点「检索」）。

- 命中 → 显示结果 + 「本次读取约 N tokens」，同时记一条 `recall` 事件
- 未命中 → 提示「已记一条」，这条会出现在**未命中**页签里等你补

> **为什么不边打字边搜**：那样每敲一个字都会记一条未命中，
> 真正的信号会被噪音冲掉。所以必须显式提交。

> **命中率为什么可能是 0%**：它 = `cite` ÷ `recall`。
> 检索会记 `recall`（分母），但 `cite`（分子）需要模型**真的用上某条记忆后回填**。
> 搜到不等于用到——若搜到就算命中，命中率会虚高到接近 100%，就没意义了。

## 四、五个页签各自干什么

| 页签 | 一句话 | 什么时候去 |
|---|---|---|
| **本项目** | 只看当前项目的记忆 | 做某个项目的活，想找这个项目的坑 |
| **记录流** | INBOX 表格的全部行 | 处理刚记的想法、改状态、提升成档案 |
| **记忆** | **全库** 42 篇 + 检索 + 域筛选 | 找东西、看全文、编辑、批量归档 |
| **未命中** | 「我搜过但库里没有」的清单 | 补齐——这是系统唯一会自我进化的地方 |
| **总览** | 成本、三率、域统计、维护作业 | 每周看一次，知道库健不健康 |

### 记录流（第 2 个页签）

每一行可以：**开始 / 完成 / 改内容 / 提升到档案 / 删除**。

- 「提升到档案」= 把这条想法变成一篇正式记忆（会在 `personal/notes/` 下建文件）
- 可以勾选多行做批量操作

> **记录流只有个人域一份**（`~/.memory-ops/personal/INBOX.md`）。
> 工作域没有独立 INBOX——这是设计决定，不是遗漏：
> 速记是「我的想法」，天然属于个人域；需要沉淀成项目知识的，用「提升到档案」搬过去。

### 未命中（第 4 个页签）

按「问过几次」**降序**排。这样最该补的排在最前。

五态：观察中 → 该补了（≥3 次）→ 草稿待确认 → 验证期内 → 已验证生效

点「写结论」→ 填内容 → 「确认落库」。
**草稿必须你点确认才进库**，系统不会自动写。

### 总览（第 5 个页签）

顶栏 5 个数字，**注意它们不是同一个东西**：

| 指标 | 你当前的值 | 含义 |
|---|---|---|
| **常驻前缀** | 225 tokens | **每个请求都要付**的那部分（skill description 54 + 目录框架 171） |
| **索引层体积** | 316 tokens | 所有 `layer: l0` 文件之和，**只在被 read 时才付费** |
| **命中率** | 视使用而定 | 30 天内 cite ÷ recall。**要模型回填 `cite` 才会有分子**，否则恒为 0 |
| 待你处理 | 2 | 需你拍板的条数 |
| 过期率 | 0% | stale + archived ÷ 总数 |

> **这两个 token 数字千万别混用**：按「索引层」去优化会去删索引表，
> 但索引表根本不在每请求前缀里，删了一分钱省不下来。要省钱动的是 skill description。

#### 预算账本怎么读

账本有 4 行，**关键不是数字，是「什么时候付费」**：

| 行 | 你当前的值 | 付费方式 | 超了怎么办 |
|---|---|---|---|
| **L0 常驻前缀** | 225 / 1024 | **每请求付费** | 压缩 skill description |
| L1 索引层 | 3515 / 2048 ⚠️ 超 | 按需加载 | 拆索引文件（不影响每请求账单） |
| L2 详情层 | 61,327 | 按需加载 | 关注**单篇**体积，不是总量 |
| L0\* 索引文件合计 | 316 | 按需加载 | 这数字大不代表贵 |

> **L0 和 L0\* 是两回事**，这是最容易混的地方：
> - **L0 常驻前缀 225** = skill description（26+28）+ 目录框架（171），**每个请求都付**
> - **L0\* 索引文件合计 316** = 两个 `index.md` 的体积，**只在被 read 时才付**
>
> 按 316 去优化会去删索引表，但索引表不在每请求前缀里，删了一分钱省不下来。

#### 常驻前缀展开后看到什么

点顶栏「常驻前缀」那一格，会展开两栏：

| 栏 | 内容 |
|---|---|
| **每请求付费** | 每个 skill 的 description（逐条列出）+ 目录框架文字 |
| **按需加载** | 每个 `layer: l0` 的索引文件（逐条列出，可点击打开） |

如果你看到「读不到 skill 列表」的红条：说明宿主的 `ctx.get("skills")` 没返回服务，
此时只统计到框架的 171，**这个数字是偏小的**。条上会写清原因。

#### 域统计能下钻

点域标题（如「▸ 工作域 · sz-web」）会展开，列出这个域下**每一篇**：

- 按 tokens **降序**排，最重的排最前
- 每条显示：标题、路径、层、状态、行数、是否超 80 行
- 点标题直接打开详情

这样「sz-web 35 篇 / 63,030 tokens」这个数字就能验证了——
你第一眼会看到最重的 3 篇是「系统概要设计 5036」「接口契约 4651」「Token 消耗分析 4644」。

下面还有：三率、库健康、域统计、**维护作业**、导出。

## 五、维护作业（总览底部）

五个按钮，都是**先预览、再执行**——它们会改记忆的可信度或内容，所以默认不自动跑。

| 作业 | 你点它之前会看到 | 点执行后 |
|---|---|---|
| **修补** | 哪些篇缺 frontmatter / status 非法 | 只补 frontmatter，**正文一字不动** |
| **锚点校验** | 哪些锚点失效、失效在哪 | 把失效的标为待复核 |
| **减重** | 每篇能省几行、建议拆哪节 | 执行无损压缩（去空行） |
| **爬升** | 哪条会被升、凭什么 | 按计划升一级（最多到 reinforced） |
| **复盘** | 这周动了什么、下周该做什么 | 只读，不改库 |

### 关于「修补」——这是你之前「插件好像没工作」的真正原因

真实库原本有 **34 篇没有 frontmatter**、**7 篇 status 是非法值 `active`**。
缺这些字段会导致一串**静默失效**：

| 缺什么 | 后果 |
|---|---|
| `status` | 读成 `active`（不在合法枚举里）→ **待你处理队列永远空** |
| `layer` | 读成空 → 预算账本 L0/L1/L2 三段统计不出来 |
| `updated` | 读成空 → 永远不提示到期退役 |

**这些已经修好了。** 现在库的健康状况是：42 篇全部元数据完整、待拍板 2 条、确认率 100%。

> 以后如果又从别处导入一批裸 Markdown，「修补」页签会重新出现数字，点一下就补上。

### 关于「减重」——别期待它能省很多

真实库 14 篇超限，机械压缩**只能省十几行**。

这是**对的**：无损压缩只删空行和行尾空格。如果它显示「省了 800 行」，
那才说明它在删你的真内容。真正长的内容要你自己摘要或拆文件，系统只给拆分建议。

## 六、agent 怎么用你的记忆

这部分你不需要操作，但知道它怎么工作有助于理解「为什么要有索引层」。

| 工具 | 谁调 | 干什么 |
|---|---|---|
| `memory_recall` | **模型自己** | 按关键词检索。命中记 cite，未命中记 miss |
| `memory_write` | **模型自己** | 写新记忆（G2 捕获走记录流，G1 直述可直接落档案） |

所以「未命中」页签里的内容，很多是**模型搜不到东西时留下的痕迹**——
那正是「该给库补什么」的准确信号。

> **维护作业不对 agent 开放**（修补 / 锚点校验 / 减重 / 爬升 / 复盘只在 UI 与路由上）。
> 这是有意的：这五项会改记忆的可信度或内容，必须由人点。
> agent 只能「读」（recall）和「追加」（write），不能改既有结论的状态。

> **这里有个待补的缺口**：`memory_write` 目前用 `actions.store.createEntry` 直接落盘，
> 没走 `actions.capture` 的每日 50 条 / 单会话 15 条熔断（`capture` 有，`mode=entry` 没有）。
> 单人使用下问题不大，但严格说 G2 的限流只覆盖了 `mode=inbox`。

## 八、故障排查

### 左侧栏没有「记忆库」

按顺序查（命令分系统给，别跨系统抄）：

**第 1 步 · 桥活着吗**

跑 §零 的 healthCheck。`ok:true` 说明 host 半体正常，问题在浏览器端。

**第 2 步 · 插件装了吗**

确认 profile 的 `node_modules` 里有这个包。注意 **Windows 上 DSH 数据根不一定是 `C:\Users\<你>\.dsh`**，
如果装 DSH 时改过位置（例如本仓库所在的机器是 `F:\dsh-home`），要换成实际那个。

*macOS*

```bash
ls -l ~/.dsh/profiles/desktop/node_modules/@memory-ops/
```

*Windows（PowerShell）*

```powershell
# 先确认你的 DSH 数据根，下面按 F:\dsh-home 举例
echo $env:DSH_PROFILE_DIR
Get-ChildItem "$env:DSH_PROFILE_DIR\node_modules\@memory-ops" | Format-Table Name,LinkType,Target
```

看到 `dsh-plugin` 即可。本地路线它是指向仓库的软链；git 路线是真实目录。

**第 3 步 · 产物是新的吗**

改了源码**必须**重新构建，`client.js` 的时间戳应该晚于你的改动。

*macOS*

```bash
cd ~/Desktop/dsh/memory-ops-dsh && pnpm build
ls -l packages/dsh-plugin/lib/
```

*Windows*

```powershell
cd G:\memory-ops-dsh; pnpm build
Get-ChildItem packages\dsh-plugin\lib | Select-Object Name,Length,LastWriteTime
```

**第 4 步 · 刷新页面**

浏览器半体是页面加载时注入的，**构建完必须刷新页面**（或重启 GUI）。
这一步最常被漏掉：代码改了、构建也跑了，界面却不变。

> 如果你是**路线 A（git 装）**，第 3 步不适用——产物在仓库里已经构建好了，
> 改不了源码。这种情况下「界面没变」通常是 DSH 版本不匹配（`engines.dsh` 不满足），
> 去 Plugins 页看该条目有没有报错。

### 加了新路由但 curl 404 / 报 unauthorized

运行中的进程用的还是**旧产物**。构建 + 重启宿主才生效。

### 「本项目」是 0 条

**先看有没有琥珀色降级条**，两种情况完全不同：

- **有降级条** → 没认出项目。按顺序查：
  1. `work/` 下有没有这个项目的 `index.md`？没有就先建（§负三 第 3 步）
  2. **项目目录名是否等于 `git remote get-url origin` 里的仓库名**（去掉 `.git`）。
     这是最常见的失败原因：remote 叫 `memory-ops-dsh`、目录却叫 `demo`，永远对不上
  3. 目录名和 remote 都对，但 cwd 是分支目录（`V2.1.25-dev` 这类）——
     这种情况**不要**再想别名表，`aliases` 已废弃。改用：给该分支所在仓库
     建一个与 remote 同名的项目目录；若它确实是独立子模块，就单独建项目
- **没有降级条** → 这个项目确实还没沉淀，去「记忆」页签看全库。

### 会话「记忆」tab 是空的，但面板里明明有 35 篇

这一栏回答的是「**本会话**注入了什么」，不是「库里有什么」。三件事要分开看：

| 看到什么 | 意思 |
|---|---|
| `本次注入 0` + 「本会话还没有检索记录」 | 这个会话里 agent 一次都没调 `memory_recall` — 正常，它只在需要时检索 |
| `本次注入 N` + 有「为什么注入」卡片 | 正常。每条卡片写明命中了哪个词、哪次检索、多少 tokens |
| 有注入但「为什么注入」为空 | 事件里没有可回指的条目 id（旧版本写入的记录），现在会直说 |

> 早先这里有个 bug：它统计的是**全库**最近 200 条事件，而且「为什么注入」
> 只在传 `query` 时才有内容——而会话 tab 从来不传 query。于是它恒显示
> 「本会话还没有检索记录」，与上面「本次注入 3」自相矛盾。已修：按会话过滤 + 从事件派生原因。

### 点了「确认」没反应 / 报「非法状态迁移」

已修。若仍看到，说明**跑的是旧产物**：`pnpm run build` 然后刷新页面（见 §八）。

错误原文形如 `非法状态迁移：hypothesis → confirmed`，
那是状态机用错了表：UI 的确认按钮走的是「人拍板表」，允许直接确认 hypothesis。
只有「自动爬升」才必须逐级（hypothesis → observed → reinforced → confirmed）。

### 常驻前缀一直显示 171，不是 361

已修。原因是宿主的 `skills.list()` 是**异步**的，插件当数组用了：
`all.filter is not a function` → 被吞成「读不到 skill」→ 只剩框架 171。

判据：点开「常驻前缀 → 构成」，如果写着红色「skills.list() 抛错」，就是这个问题。
正常时应显示 `state: ok`，且 `catalogTokens` 大于 0、`billedTokens = catalog + 171`。

### 「待你处理」是空的，但库里有 42 篇

说明所有条目都已有合法 status 且无需拍板。
如果你刚导入过裸 Markdown，去 **总览 → 维护作业 → 修补** 看有没有数字。

### 命中率显示「—」

分母为 0，**不是 0%**。「算不出来」和「是零」是两件事。
去「记忆」页签检索几次，就会有数了。

### 数据在哪 / 怎么备份

**macOS**

```
~/.memory-ops/
├── personal/     个人域 7 篇 + INBOX.md
├── work/sz-web/  工作域 35 篇
├── archive/      归档
└── .state/       events.jsonl（只追加）+ misses.json
```

**Windows**

```
C:\Users\<你的用户名>\.memory-ops\
├── personal\     个人域 7 篇 + INBOX.md
├── work\sz-web\  工作域 35 篇
├── archive\      归档
└── .state\       events.jsonl（只追加）+ misses.json
```

> 如果你设过环境变量 `MEMORY_OPS_ROOT`，实际位置以它为准——
> 上面两条 healthCheck 返回的 `root` 字段就是真相。

全是 Markdown，可以直接 `git` 管、也可以直接手改。
**备份就是复制这个目录**。

*macOS*

```bash
cp -R ~/.memory-ops ~/.memory-ops.bak-$(date +%Y%m%d)
```

*Windows（PowerShell）*

```powershell
$src = Join-Path $env:USERPROFILE '.memory-ops'
$dst = "$src.bak-$(Get-Date -Format yyyyMMdd)"
Copy-Item $src $dst -Recurse
Write-Host "已备份到 $dst"
```

### 系统差异速查（跨系统抄命令前先看这张）

| 事项 | macOS | Windows |
|---|---|---|
| 设代理（临时） | `export HTTPS_PROXY=…` | `$env:HTTPS_PROXY = '…'` |
| 设代理（永久） | 写 `~/.zshrc` 再 `source` | `[Environment]::SetEnvironmentVariable(…, 'User')` 后重开窗口 |
| 路径分隔符 | `/` | `\`（`/` 多数情况也行） |
| 家目录 | `~` | `$env:USERPROFILE` 或 `C:\Users\<你>` |
| 发 HTTP 请求 | `curl -s <url>` | `curl.exe -s <url>` 或 `Invoke-WebRequest` |
| 看文件时间戳 | `ls -l <目录>` | `Get-ChildItem <目录> \| Select LastWriteTime` |
| 递归复制 | `cp -R <源> <目标>` | `Copy-Item <源> <目标> -Recurse` |
| 列软链指向 | `ls -l` | `Get-ChildItem \| Format-Table LinkType,Target` |
