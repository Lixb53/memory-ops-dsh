> 产品设计立场见 [`product.md`](./product.md)，本文不重复。

## 负一、第一次用，从哪开始（照着做就行）

> 记忆库不是「装好就自动帮你」的工具，它的设计假设是**人负责拍板、agent 负责取用**。
> 所以「开始使用」= 先把这四件事做一遍，之后它才会开始真的帮你。

### 第 1 步：确认它在读你的库（10 秒）

看「总览」页签顶部：**待你处理**应该有个非零数字，**域统计**里应该能看到 `sz-web 35 篇`。
如果是 0 篇，先跳到 §八 排查，别急着改数据。

### 第 2 步：清掉「待你处理」（今天的 5 分钟）

进「总览 → 待你处理」，把那 2 条推断逐条**确认**或**驳回**。
这一步不能跳过，原因很实际：**未处理完的推断会一直占着队列**，
而「确认率」这个指标在它们处理完之前没有意义。

### 第 3 步：让 agent 知道该读什么（这才是重点）

记忆库的读者主要是 agent，而 agent 取用靠三样东西：

| 东西 | 在哪 | 作用 |
|---|---|---|
| `memory_recall` 工具 | 模型自己调 | 按关键词检索，命中记 `cite`，未命中记 `miss` |
| 项目索引 `work/<项目>/index.md` | 库内 | 告诉 agent「哪类问题该读哪个目录」 |
| `aliases` | 上面那个文件的 frontmatter | 让「本项目」能从 cwd 认出项目（见 §二） |

所以「开始使用」的那一刻，就是**你在一个真实会话里问一个你踩过坑的问题**，
然后看 agent 有没有调 `memory_recall` 命中它。命中了，这套机制就转起来了。

### 第 4 步：跑一周后再看三个数

一周内**真的提问几次**，再回来看「总览」：

| 指标 | 健康值 | 不健康说明什么 |
|---|---|---|
| 命中率 | > 60% | 分母在涨、分子为 0 → agent 搜到但没用上，或库里的东西不相关 |
| 确认率 | > 70% | 推断太多没人拍板 → 回第 2 步 |
| 未命中「该补了」 | 越少越好 | 这些是**你自己反复问到、但库里没有**的问题，最该补 |

> **一开始命中率很可能是「—」而不是 0%**：`—` 表示分母为 0（还没检索过），
> 和「检索过但全落空」是两件事。别把算不出来当成算出来是零。

### 别做的三件事

| 别做 | 为什么 |
|---|---|
| 把整个库喂给 agent | 那会毁掉「常驻前缀 361 tokens」这个第一指标，退化成第二个知识库 |
| 手动批量改 `status` | 状态流转有唯一合法路径，绕过它会打乱三率口径 |
| 指望它自动往里写结论 | 设计上只产出草稿。**人确认才落库**，这是它敢被信任的前提 |

## 零、先确认它活着

在你开始点之前，先花 10 秒确认插件真的在跑。有两种确认方式：

**方式一：看桥（最可靠）**

```bash
# 端口换成你当前 GUI 的地址（终端里 dsh web 启动时会打印，形如 http://127.0.0.1:63097）
curl -s http://127.0.0.1:63097/api/dsh-memory-ops/healthCheck
```

> ⚠️ 早先这里写死 `54000`，那是 desktop 版的端口；`dsh web` 的端口是每次启动随机分配的。
> 端口不对会得到 `connection refused`，看起来像「插件没装」，其实只是敲错了地方。
> 取当前端口的办法：看 GUI 地址栏（`http://127.0.0.1:<端口>/?token=…`）。

期望看到：

```json
{"ok":true,"root":"/Users/zeze/.memory-ops","routes":34}
```

- `ok:true` → 插件已加载，桥在监听
- `root` → 它正在读哪个目录（**这必须是你有记忆的那个目录**）
- `routes` → 能力条数。**当前应是 34**；如果你是 33，说明插件产物是旧的，见 §八

**方式二：看界面**

左侧栏（最左那一列图标）往下找，**「上下文洞察」下面有一个「记忆库」**。
点它，右侧主区域会出现 5 个页签：本项目 / 记录流 / 记忆 / 未命中 / 总览。

> 如果左侧栏没有「记忆库」，先看 §八 的排查清单，不要急着改数据。

## 二、最常见的困惑：「本项目」显示 0 条

这一节**改写过两次**，因为上一版把 bug 写成了「设计如此」。

### 先说结论：0 条有两种完全不同的原因

| 画面 | 真正的原因 | 该怎么办 |
|---|---|---|
| 0 条 + 顶部**没有**降级条 | 这个项目**确实**还没有记忆 | 去「记忆」页签看全库，或给它记一条 |
| 0 条 + 顶部**有琥珀色降级条** | 没认出当前是哪个项目 | 看降级条写的「原因」，按提示登记 `aliases` |

**降级条是真话，空列表不是。** 只要它出现，就说明系统**不确定**这个项目是谁——
此时它退回「全部记忆」，而不是假装「这个项目没有」。

### 「本项目」判定项目的方式

不是拿目录末段当项目名（那是旧实现，见下面的事故），而是：

1. 取当前会话的 **cwd**（例如 `/Users/…/work/zhongxing/V2.1.25-dev`）
2. 在 `work/<项目>/index.md` 的 frontmatter 里读 **项目名 + `aliases`**
3. cwd 里任一段**等于**别名 → 精确命中；**以「别名 + `-`」开头** → 前缀命中

所以 `V2.1.25-dev`、`submodule/sz-web-dzh-gslx` 这些目录都能被认成 **sz-web**，
前提是它们被登记在 `~/.memory-ops/work/sz-web/index.md` 里：

```yaml
aliases: [V2.1.25-dev, V2.1.24-dev, sz-web-dzh-gsjq, sz-web-dzh-gslx, sz-web-dzh-gslz, gslx]
```

> **新项目的初始化动作**：`work/<项目>/` 下建一个 `index.md`，
> 把分支目录、子仓库目录名写进 `aliases`。不登记就只能靠猜，而猜错就显示 0 条。

### 你的记忆分布

| 域 | 篇数 |
|---|---|
| 工作域 · sz-web | **35** |
| 个人域 | **7** |
| **合计** | **42** |

**想看全部 42 篇 → 点「记忆」页签**，范围选「**全部记忆**」（这是默认值）。

> ⚠️ 上一版这里写错了两次：
> ①「记忆」页签曾也按项目过滤，于是它和「本项目」显示同一份东西——已修，默认全库；
> ② 更早还把「本项目 0 条」解释成「设计如此」，而真实原因是 cwd 末段（`V2.1.25-dev`）

> 「本项目」底部的空态里有三个按钮：**记一条 / 看未命中 / 重新读取**。
> 「记一条」会跳到记录流，不是跳去新建档案。

## 三、日常怎么用：三个高频动作

### 动作一：随手记一条（最常用）

**入口**：右侧栏 →「快速捕获」，或输入框打 `/remember`

1. 选类型（想法 / 计划 / 问题 / 待办 / 决策）
2. 写一句话（**贴多行会自动拆分逐条存**）
3. `⌘ + Enter` 提交（或点「记一条」）

存进去的是**记录流**（`~/.memory-ops/personal/INBOX.md` 的一行），不是档案。
存完 30 秒内可以点「撤销」。

> **隐私闸门**：内容里出现密钥、私钥、身份证、内网 IP 会被**拒写**，
> 并给你一段脱敏后的文本，点「填入脱敏文本」可以改完再存。

### 动作二：处理待办（每周一次就够）

**入口**：侧栏「记忆库」→ **总览** 页签 → 「待你处理」区

这里放的是**需要你拍板**的条目：推断待确认的、到期该退役的。

每条有这些按钮：

| 按钮 | 什么时候点 | 点了以后 |
|---|---|---|
| **确认** | 这条是对的，留下来 | 就地变「已确认」，置信度 0.9 |
| **驳回…** | 这条不对 | 跳到详情页，**那里**有理由输入框（理由必填） |
| 看详情 | 想看全文和证据链 | 打开详情 |
| 再留 90 天 | 还有用，但现在没空处理 | 到期计时重置 |

> **点了没反应？** 现在不会了。每个按钮点完，队列上方都会出现一条结果条：
> 成功是绿色「确认」，失败是红色并**带出宿主的原始错误**（例如
> `确认失败：非法状态迁移：hypothesis → confirmed`）。
> 早先这里是完全静默的：失败连一句提示都没有，所以「确认无效」看起来像功能坏了。

> **驳回为什么必须写理由**：驳回后 30 天内它不再参与纠错。
> 30 天后回看时，没有理由就说不清当初为什么否掉，只能原样恢复——那这机制就白转一圈。

> **驳回为什么在总览里点了要跳页**：总览是「一眼一批」的列表，塞个输入框会把节奏打断；
> 详情页才放得下理由框。所以总览的按钮标了省略号「驳回**…**」——它表示「还有下一步」。

你当前库里有 **2 条**待拍板。

#### 为什么「确认」过去必然失败（已修）

状态机有两张表，之前用错了一张：

| 表 | 回答的问题 | hypothesis → confirmed |
|---|---|---|
| 自动爬升表 | 「系统能不能自己把它升上去」 | ❌ 不许跳级 |
| **人拍板表** | 「人看完说它对，能不能留」 | ✅ 允许 |

UI 的确认按钮走的是 `setStatus`，而它当时用自动表校验。
待处理队列里最常见的就是 hypothesis（推断待确认），于是**每次都报非法迁移**。
这等于「确认按钮在设计上永远不该能用」——已改为人表校验。

### 动作三：检索（让「命中率」有意义）

**入口**：侧栏「记忆库」→ **记忆** 页签 → 顶部搜索框

输入关键词，**按回车**（或点「检索」）。

- 命中 → 显示结果 + 「本次读取约 N tokens」，同时记一条 `recall` 事件
- 未命中 → 提示「已记一条」，这条会出现在**未命中**页签里等你补

> **为什么不边打字边搜**：那样每敲一个字都会记一条未命中，
> 真正的信号会被噪音冲掉。所以必须显式提交。

> **命中率为什么可能是 0%**：它 = `cite` ÷ `recall`。
> 检索会记 `recall`（分母），但 `cite`（分子）需要模型**真的用上某条记忆后回填**。
> 搜到不等于用到——若搜到就算命中，命中率会虚高到接近 100%，就没意义了。

## 四、五个页签各自干什么

| 页签 | 一句话 | 什么时候去 |
|---|---|---|
| **本项目** | 只看当前项目的记忆 | 做某个项目的活，想找这个项目的坑 |
| **记录流** | INBOX 表格的全部行 | 处理刚记的想法、改状态、提升成档案 |
| **记忆** | **全库** 42 篇 + 检索 + 域筛选 | 找东西、看全文、编辑、批量归档 |
| **未命中** | 「我搜过但库里没有」的清单 | 补齐——这是系统唯一会自我进化的地方 |
| **总览** | 成本、三率、域统计、维护作业 | 每周看一次，知道库健不健康 |

### 记录流（第 2 个页签）

每一行可以：**开始 / 完成 / 改内容 / 提升到档案 / 删除**。

- 「提升到档案」= 把这条想法变成一篇正式记忆（会在 `personal/notes/` 下建文件）
- 可以勾选多行做批量操作

> **记录流只有个人域一份**（`~/.memory-ops/personal/INBOX.md`）。
> 工作域没有独立 INBOX——这是设计决定，不是遗漏：
> 速记是「我的想法」，天然属于个人域；需要沉淀成项目知识的，用「提升到档案」搬过去。

### 未命中（第 4 个页签）

按「问过几次」**降序**排。这样最该补的排在最前。

五态：观察中 → 该补了（≥3 次）→ 草稿待确认 → 验证期内 → 已验证生效

点「写结论」→ 填内容 → 「确认落库」。
**草稿必须你点确认才进库**，系统不会自动写。

### 总览（第 5 个页签）

顶栏 5 个数字，**注意它们不是同一个东西**：

| 指标 | 你当前的值 | 含义 |
|---|---|---|
| **常驻前缀** | 225 tokens | **每个请求都要付**的那部分（skill description 54 + 目录框架 171） |
| **索引层体积** | 316 tokens | 所有 `layer: l0` 文件之和，**只在被 read 时才付费** |
| **命中率** | 视使用而定 | 30 天内 cite ÷ recall。**要模型回填 `cite` 才会有分子**，否则恒为 0 |
| 待你处理 | 2 | 需你拍板的条数 |
| 过期率 | 0% | stale + archived ÷ 总数 |

> **这两个 token 数字千万别混用**：按「索引层」去优化会去删索引表，
> 但索引表根本不在每请求前缀里，删了一分钱省不下来。要省钱动的是 skill description。

#### 预算账本怎么读

账本有 4 行，**关键不是数字，是「什么时候付费」**：

| 行 | 你当前的值 | 付费方式 | 超了怎么办 |
|---|---|---|---|
| **L0 常驻前缀** | 225 / 1024 | **每请求付费** | 压缩 skill description |
| L1 索引层 | 3515 / 2048 ⚠️ 超 | 按需加载 | 拆索引文件（不影响每请求账单） |
| L2 详情层 | 61,327 | 按需加载 | 关注**单篇**体积，不是总量 |
| L0\* 索引文件合计 | 316 | 按需加载 | 这数字大不代表贵 |

> **L0 和 L0\* 是两回事**，这是最容易混的地方：
> - **L0 常驻前缀 225** = skill description（26+28）+ 目录框架（171），**每个请求都付**
> - **L0\* 索引文件合计 316** = 两个 `index.md` 的体积，**只在被 read 时才付**
>
> 按 316 去优化会去删索引表，但索引表不在每请求前缀里，删了一分钱省不下来。

#### 常驻前缀展开后看到什么

点顶栏「常驻前缀」那一格，会展开两栏：

| 栏 | 内容 |
|---|---|
| **每请求付费** | 每个 skill 的 description（逐条列出）+ 目录框架文字 |
| **按需加载** | 每个 `layer: l0` 的索引文件（逐条列出，可点击打开） |

如果你看到「读不到 skill 列表」的红条：说明宿主的 `ctx.get("skills")` 没返回服务，
此时只统计到框架的 171，**这个数字是偏小的**。条上会写清原因。

#### 域统计能下钻

点域标题（如「▸ 工作域 · sz-web」）会展开，列出这个域下**每一篇**：

- 按 tokens **降序**排，最重的排最前
- 每条显示：标题、路径、层、状态、行数、是否超 80 行
- 点标题直接打开详情

这样「sz-web 35 篇 / 63,030 tokens」这个数字就能验证了——
你第一眼会看到最重的 3 篇是「系统概要设计 5036」「接口契约 4651」「Token 消耗分析 4644」。

下面还有：三率、库健康、域统计、**维护作业**、导出。

## 五、维护作业（总览底部）

五个按钮，都是**先预览、再执行**——它们会改记忆的可信度或内容，所以默认不自动跑。

| 作业 | 你点它之前会看到 | 点执行后 |
|---|---|---|
| **修补** | 哪些篇缺 frontmatter / status 非法 | 只补 frontmatter，**正文一字不动** |
| **锚点校验** | 哪些锚点失效、失效在哪 | 把失效的标为待复核 |
| **减重** | 每篇能省几行、建议拆哪节 | 执行无损压缩（去空行） |
| **爬升** | 哪条会被升、凭什么 | 按计划升一级（最多到 reinforced） |
| **复盘** | 这周动了什么、下周该做什么 | 只读，不改库 |

### 关于「修补」——这是你之前「插件好像没工作」的真正原因

真实库原本有 **34 篇没有 frontmatter**、**7 篇 status 是非法值 `active`**。
缺这些字段会导致一串**静默失效**：

| 缺什么 | 后果 |
|---|---|
| `status` | 读成 `active`（不在合法枚举里）→ **待你处理队列永远空** |
| `layer` | 读成空 → 预算账本 L0/L1/L2 三段统计不出来 |
| `updated` | 读成空 → 永远不提示到期退役 |

**这些已经修好了。** 现在库的健康状况是：42 篇全部元数据完整、待拍板 2 条、确认率 100%。

> 以后如果又从别处导入一批裸 Markdown，「修补」页签会重新出现数字，点一下就补上。

### 关于「减重」——别期待它能省很多

真实库 14 篇超限，机械压缩**只能省十几行**。

这是**对的**：无损压缩只删空行和行尾空格。如果它显示「省了 800 行」，
那才说明它在删你的真内容。真正长的内容要你自己摘要或拆文件，系统只给拆分建议。

## 六、agent 怎么用你的记忆

这部分你不需要操作，但知道它怎么工作有助于理解「为什么要有索引层」。

| 工具 | 谁调 | 干什么 |
|---|---|---|
| `memory_recall` | **模型自己** | 按关键词检索。命中记 cite，未命中记 miss |
| `memory_write` | **模型自己** | 写新记忆（G2 捕获走记录流，G1 直述可直接落档案） |

所以「未命中」页签里的内容，很多是**模型搜不到东西时留下的痕迹**——
那正是「该给库补什么」的准确信号。

> **维护作业不对 agent 开放**（修补 / 锚点校验 / 减重 / 爬升 / 复盘只在 UI 与路由上）。
> 这是有意的：这五项会改记忆的可信度或内容，必须由人点。
> agent 只能「读」（recall）和「追加」（write），不能改既有结论的状态。

> **这里有个待补的缺口**：`memory_write` 目前用 `actions.store.createEntry` 直接落盘，
> 没走 `actions.capture` 的每日 50 条 / 单会话 15 条熔断（`capture` 有，`mode=entry` 没有）。
> 单人使用下问题不大，但严格说 G2 的限流只覆盖了 `mode=inbox`。

## 八、故障排查

### 左侧栏没有「记忆库」

按顺序查：

1. **桥活着吗**：跑 §零 的 curl。`ok:true` 说明 host 半体正常，问题在浏览器端。
2. **插件装了吗**：`ls ~/.dsh/profiles/desktop/node_modules/@memory-ops`
   应该有 `dsh-plugin` 指向仓库目录的软链。
3. **产物是新的吗**：`ls -la packages/dsh-plugin/lib/`
   改了源码**必须**重新构建，`client.js` 的时间戳应该晚于你的改动：
   ```bash
   cd /Users/zeze/Desktop/dsh/memory-ops-dsh && pnpm run build
   ```
4. **重启 GUI**：浏览器半体是页面加载时注入的，**构建完必须刷新页面**（或重启 GUI）。

### 加了新路由但 curl 404 / 报 unauthorized

运行中的进程用的还是**旧产物**。构建 + 重启宿主才生效。

### 「本项目」是 0 条

**先看有没有琥珀色降级条**，两种情况完全不同：

- 有降级条 → 没认出项目。按 §二 把当前目录登记进 `work/<项目>/index.md` 的 `aliases`。
  （`V2.1.25-dev` 这类分支目录**必须登记**，它的名字里根本不含 `sz-web`。）
- 没有降级条 → 这个项目确实还没沉淀，去「记忆」页签看全库。

### 会话「记忆」tab 是空的，但面板里明明有 35 篇

这一栏回答的是「**本会话**注入了什么」，不是「库里有什么」。三件事要分开看：

| 看到什么 | 意思 |
|---|---|
| `本次注入 0` + 「本会话还没有检索记录」 | 这个会话里 agent 一次都没调 `memory_recall` — 正常，它只在需要时检索 |
| `本次注入 N` + 有「为什么注入」卡片 | 正常。每条卡片写明命中了哪个词、哪次检索、多少 tokens |
| 有注入但「为什么注入」为空 | 事件里没有可回指的条目 id（旧版本写入的记录），现在会直说 |

> 早先这里有个 bug：它统计的是**全库**最近 200 条事件，而且「为什么注入」
> 只在传 `query` 时才有内容——而会话 tab 从来不传 query。于是它恒显示
> 「本会话还没有检索记录」，与上面「本次注入 3」自相矛盾。已修：按会话过滤 + 从事件派生原因。

### 点了「确认」没反应 / 报「非法状态迁移」

已修。若仍看到，说明**跑的是旧产物**：`pnpm run build` 然后刷新页面（见 §八）。

错误原文形如 `非法状态迁移：hypothesis → confirmed`，
那是状态机用错了表：UI 的确认按钮走的是「人拍板表」，允许直接确认 hypothesis。
只有「自动爬升」才必须逐级（hypothesis → observed → reinforced → confirmed）。

### 常驻前缀一直显示 171，不是 361

已修。原因是宿主的 `skills.list()` 是**异步**的，插件当数组用了：
`all.filter is not a function` → 被吞成「读不到 skill」→ 只剩框架 171。

判据：点开「常驻前缀 → 构成」，如果写着红色「skills.list() 抛错」，就是这个问题。
正常时应显示 `state: ok`，且 `catalogTokens` 大于 0、`billedTokens = catalog + 171`。

### 「待你处理」是空的，但库里有 42 篇

说明所有条目都已有合法 status 且无需拍板。
如果你刚导入过裸 Markdown，去 **总览 → 维护作业 → 修补** 看有没有数字。

### 命中率显示「—」

分母为 0，**不是 0%**。「算不出来」和「是零」是两件事。
去「记忆」页签检索几次，就会有数了。

### 数据在哪 / 怎么备份

```
~/.memory-ops/
├── personal/     个人域 7 篇 + INBOX.md
├── work/sz-web/  工作域 35 篇
├── archive/      归档
└── .state/       events.jsonl（只追加）+ misses.json
```

全是 Markdown，可以直接 `git` 管、也可以直接手改。
**备份就是复制这个目录**：

```bash
cp -R ~/.memory-ops ~/.memory-ops.bak-$(date +%Y%m%d)
```
