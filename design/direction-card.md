## 零、前置约束：不得发明颜色

本产品**已有设计系统**，且代码里已经强制执行：

- `packages/dsh-plugin/src/client/styles.ts` 开头写明：只用宿主主题 token（`--dsw-alias-*`），不写死颜色；
- `docs/product.md` §六 规定字号 12/14/16/20/24、间距 4 的倍数、圆角 6/8/12、阴影 0 处（除浮层）。

因此 **v4 不引入任何新色板**。方向卡的作用不是选颜色，而是规定**已有 token 的使用规则**——这才是当前界面混乱的真实原因（见 §三 诊断）。

### 原型的 token 实现约定（重要，避免误读）

`prototype/` 是脱离宿主运行的独立 HTML，拿不到 `--dsw-alias-*` 的真实值。因此原型在
`prototype/tokens.css` 里用 `oklch` 定义了一组**同名变量**作为占位实现：

```css
--dsw-alias-label-primary: oklch(...);   /* 占位：落地时整段删除 */
```

**落地规则**：`prototype/tokens.css` 整个文件在移植进插件时**必须删除**，
所有 `var(--dsw-alias-*)` 由宿主提供真实值。原型里出现的任何颜色值都不得抄进代码。

这条写在这里，是因为「原型颜色被误当设计决策抄进产品」是本仓已经发生过的事
（`docs/product.md` §六：自建 token 只存在于 HTML 设计稿里，未进入代码）。

## 一、风格定位：**编辑感（Editorial）**——明确选一个，不含糊

### 选择理由

这个产品的内容本体是**人可审的 Markdown 台账**：一条记忆 = 标题 + 状态 + 证据出处 + 体积 + 引用史。
它天然是「带批注的档案」，不是「一堆功能卡片」。

编辑感的三条手法正好对上当前三个病灶：

| 病灶 | 编辑感如何解决 |
|---|---|
| 卡片堆叠导致所有区块视觉重量相同 | 用**细分隔线 + 空白**分组，去掉卡片边框；重量靠字号与留白分出三级 |
| 元信息（token/日期/路径/引用次数）与正文同字号，读不出主次 | 元信息统一走**等宽字体 + 小字号 + 次要色**，一眼可分类 |
| 首屏 5 个 KPI 全是数字，没有一句话说「现在该做什么」 | 首屏第一行是**一句话结论**（编辑体的导语），数字退居其后 |

### 明确拒绝的风格（写下来防漂移）

- ❌ 玻璃拟态：宿主侧栏背景本身是纯色，叠加 blur 只会脏。
- ❌ Bento 网格：本产品数据是线性台账，Bento 会强行把不等长的内容塞进等大方格。
- ❌ 大字排版（Display 型 landing）：侧栏最窄 400px，20px 以上标题会换行成灾。
- ❌ 暗黑中性：必须跟随宿主深浅色，不能自定。

### 编辑感在本产品里的具体表现

1. **一个页面只有一处 24px**：页面导语（`.lede`）。其余全部 ≤16px。
2. **区块标题用小号 + 字距 + 上下 hairline**，不用卡片包裹。
3. **数字与路径一律等宽**。对齐规则见下方裁决。
4. **首屏第一行是一句话**，不是 KPI 阵列。

> **「数字右对齐到同一条基线」的裁决（第 2 轮评审指出与 §四 冲突）**：
>
> 原文第 3 条写的「右对齐到同一条基线」在 400px 的行内台账里做不到——
> 行内是 flex-wrap 左流，没有列可对齐。两条规则（§一-3 与 §四）互相冲突，
> 而实现悄悄选了「左流换行」，没留下裁决。
>
> **现判定**：
> - **表格型区域**（`.cost` 成本三行）→ 数字右对齐到同一基线，因为那里是真的两列。
> - **行内台账**（条目行的元信息）→ **不做右对齐**，靠「等宽 + 次要色 + 固定顺序」
>   表达这是元信息。理由：400px 下强行右对齐会让每行的元信息被挤到第二行且错位，
>   反而更难扫读。
> - 判据：**这一块的内容是否天然构成两列**。构成就右对齐；不构成就别假装。

## 二、色彩策略

### 主色：沿用宿主 `--dsw-alias-brand-primary`

**使用规则：全屏最多一处 brand 实底**，即「当前页唯一主动作」按钮。
其余任何地方（徽标底、图标、链接装饰、分隔线、进度条）**一律不得使用 brand 实底**。

> 现状违规实证：`styles.ts` 里 `.dmo-badge-brand`（15% 透明底）、`.dmo-budget-fill`
> （实底）、`.dmo-step-now`（实底）、`.dmo-bulk`（8% 底 + 28% 边框）、
> `.dmo-band-cell[data-active]`、`.dmo-chip[aria-pressed]`（实底）共 6 处消耗 brand。
> 一屏里 brand 出现 6 次，等于没有强调。

### 中性色阶：三档，只用三档

| 档 | token | 唯一用途 |
|---|---|---|
| 主文本 | `--dsw-alias-label-primary` | 标题、正文句子 |
| 次要文本 | `--dsw-alias-label-secondary` | 元信息、说明、时间、路径 |
| 分隔/边界 | `--dsw-alias-border-l1` | hairline；`border-l2` 只给可交互控件边框 |

**禁止**：把 `label-secondary` 当作正文句子色用于超过一行的段落——这是禁止清单里
「gray-400/500 作正文」的等价违规，宿主浅色主题下对比度不足。

**精确边界（5A 自检时补写，防止模糊）**：

| 场景 | 允许的颜色 | 理由 |
|---|---|---|
| 条目标题、记忆正文块、任何 ≥2 行的段落 | **必须** `label-primary` | 这是「读的内容」 |
| 单句解释 / 空态说明 / 建议卡的理由（≤ 2 行） | 允许 `label-secondary` | 这是「辅助理解」，不承担主阅读 |
| 元信息（token / 日期 / 路径 / 计数）、表头、徽标 | `label-secondary` + 等宽 | 只有几个字符，对比度压力小 |

判定口径：**用户要连续读下去的，一律 primary**。原型中记忆正文块
（`.body-block`，`app.css` L790）不设 color，继承 `body` 的 primary —— 已核对。

### 语义色：三条，各自封闭

| 色 | token | **只允许**出现在 |
|---|---|---|
| 琥珀 | `--dsw-alias-state-warn-primary` | 推断待确认 / 未命中 / 到期 / 降级 |
| 绿 | `--dsw-alias-state-success-primary` | 已确认 / 命中生效 |
| 红 | `--dsw-alias-state-error-primary` | 驳回 / 删除 / 隐私拦截 / 读取失败 |

语义色**不得**用于装饰（例如「未命中次数多」不能因为数字大就染成琥珀——次数是事实，不是告警）。
**不得**使用第二套色板表达同一语义。

## 三、字体与层级规则

### 字阶：**5 档，不多不少**（对齐 `docs/product.md` §六）

| 档 | 字号 / 行高 | 用途 | 硬约束 |
|---|---|---|---|
| T1 | 24 / 32 | **页面导语**（`.lede`，一句话结论） | **每页仅 1 处** |
| T2 | 20 / 28 | 保留档（当前未使用，见下方裁决） | — |
| T3 | 16 / 24 | 建议卡标题、条目标题、详情标题 | — |
| T4 | 14 / 22 | 正文句子、说明句、按钮、输入、区块标题 | — |
| T5 | 12 / 18 | 元信息、状态签、表头、计数 | **仅等宽或短标签**；禁止承载 >1 行文本 |

### 档位裁决记录（第 1 轮评审后补写）

评审指出方向卡 §一 说「20px 以上标题会换行成灾」，§三 又要求 T1=24px，
两条在 400px 侧栏里不能同时成立，而实现悄悄选了「0 处 T1」却没留裁决。

**裁决（2026-11-17，第 2 轮评审后修正）**：

1. **T1 = 24px 只给 `.lede`（每页一句导语），且允许折 2 行**。
   理由：正文段落的标题确实会在 400px 下换行成灾，但 `.lede` 是单句导语。
   「会换行成灾」指的是**段落级**大标题，不是单句——原措辞过宽，此处收窄。

   > ⚠️ **修正一次错判**：本文早先写「实测该句 18 字，在 400px 内单行放得下」。
   > 那是错的。实测（Chromium，视口 1200，面板 398px）：
   > `.lede` 可用宽 **359px**、字号 24px、行高 32px、**offsetHeight 64px**
   > → 实际渲染 **2 行**。
   > 所以正确结论不是「单行放得下」，而是「**允许导语折 2 行**，
   > 因为 24px 的视觉权重值得这 32px 额外高度」。
   > 把一条会被截图证伪的测量写进唯一契约，比没有裁决更糟——
   > 它会让后来者以为这是已验证的事实。
2. **T2 = 20px 保留为未使用档**，不删。理由：删了字阶就不完整，
   而它对应「页面内二级导语」这个真实需求（当前 5 页恰好都用不到）。
   写明「未使用」比删掉更诚实。
3. **区块标题归 T4（14px）+ `letter-spacing: 0.02em` + 上下 hairline**。
   原 §一 说「区块标题用小号 + 字距」，§三 把 T2 分给区块标题——两者冲突。
   现统一为 T4：区块标题是结构标记，不是视觉重点，占 T2 会与导语抢。
4. **应用外壳标签（「记忆库」）降为 T4 + 600 + 字距**。
   它不该与内容标题同级（见 §三 下方 `.panel-title` 说明）。

   > 已知代价（第 2 轮评审指出，此处明示而非隐瞒）：
   > T4 一档现在同时承担「区块标题 14/600」「正文 14/400」「按钮 14」「输入 14」。
   > 区分只靠字重与字距。这是压缩字阶到 5 档的必然代价，
   > 换来的是「不再有 10.5 / 11 / 11.5 三种肉眼不可分的字号」。
   > 若未来觉得不够分，正确做法是**重新引入 T2 给区块标题**，
   > 而不是新增 13px 这种半档。


### 现状违规实证（这是「不知道看哪」的直接原因）

`styles.ts` 实际使用了 **11 种字号**：10 / 10.5 / 11 / 11.5 / 12 / 13 / 14 / 15 / 16 / 17 / 18。

其中 10.5 与 11 与 11.5 相差 0.5px，**肉眼不可分辨**，却占用三个不同语义槽位。
结果是：卡片的「标题 13」与「元信息 11」只差 2px，第一眼无法区分主次。

v4 整改：所有 `<12px` 的字号一律并入 T5（12px），靠**颜色与等宽**区分层级，不再靠 0.5px。

### 字重策略（第二字体问题）

禁止清单指出「Inter / Geist 等作为唯一字体身份，没有任何第二字体或字重策略」。
本产品的第二身份是 **等宽字体**，语义明确：

```
元信息类（token 数、日期、路径、行号、hash、计数、状态机枚举）
  → ui-monospace, SFMono-Regular, Menlo, monospace
正文与标题
  → 继承宿主 UI 字体
```

字重只用两档：`400`（正文）/ `600`（标题与主按钮）。现状出现 650、`bold` 混用，统一为 600。

## 四、形状与间距系统

### 间距：4 的倍数，六档

```
s1=4   s2=8   s3=12   s4=16   s5=24   s6=32
```

现状违规：`padding: 7px 8px`、`padding: 6px 9px`、`margin-bottom: 7px`、`padding: 3px 9px`
—— 7 / 9 / 3 / 10.5 全部不在 4 的倍数网格上。v4 全部对齐到上述六档。

### 圆角：**四档，且按语义分配**（不是随便给）

| 值 | 语义 | 用在哪 |
|---|---|---|
| 0 | 行内标记 | 状态签、类型签、计数、条目行本身——**不做圆角** |
| 6 | 控件 | 按钮、输入框、下拉、焦点环内的小点击态 |
| 8 | 容器 | 需要边界的内容块：唯一建议卡、捕获区、提示条、错误条、侧栏外壳 |
| 12 | 浮层 | **只给**弹窗、toast |

> **圆角 8 的归属裁决**（第 1 轮评审指出原文只举两个例子，
> 导致 `.alert` / `.notice` / `.sidebar` 也用了 8 却无法判定是否越界）：
>
> 8 的语义是「**这是一个有边界的块**」，不是「只允许一个块」。
> §一 的「全屏只保留 1 张建议卡」指的是**卡片式容器**只有一个。
> 判定口径：**问「用户会不会把它当作可交互的卡片」**——
> 会（能点、能展开）→ 算卡片容器，受「只有 1 张」约束；
> 不会（只是书面提示 / 页面外框）→ 用 8 合理，不计入约束。

> 为什么 0 必须存在：现状 `styles.ts` 里 `.dmo-card` / `.dmo-kpi` / `.dmo-budget` /
> `.dmo-session-kpi` / `.dmo-skeleton` 全是 `border-radius: 8`，连 `.dmo-badge`
> 也是 9、`.dmo-tag` 是 4——实测 `border-radius` 共有 **9 种取值**
> （12px / 2px / 3px / 4px / 6px / `6px 6px 0 0` / 7px / 8px / 9px），
> 且没有一种对应「这不是容器」。
> 编辑感依赖「行不是卡片」，所以条目行与状态签的圆角必须是 0。

**禁止**：条目行、区块、KPI 一律用 8 的现状（`styles.ts` 里 `.dmo-card` / `.dmo-kpi` /
`.dmo-budget` / `.dmo-session-kpi` 全是 8，连 `.dmo-skeleton` 也是 8）。
v4 中**条目行不再是卡片**——用 hairline 分隔，圆角为 0。这是形状节奏的来源。

### 阴影：0 处，除浮层

沿用 `docs/product.md` §六。`.dmo-remember-card` 与 `.dmo-remember-toast` 保留阴影，
其余任何元素不得有 `box-shadow`。

## 五、动效原则

| 项 | 规则 |
|---|---|
| 时长 | 120ms（态切换）/ 180ms（浮层进出） |
| 缓动 | `cubic-bezier(0.2, 0, 0, 1)` |
| 触发 | **只由用户动作触发**（hover / focus / 点击 / 展开） |
| 禁止 | 滚动进入时 fade-up / slide-up；卡片 hover `scale(1.05)` |
| 加载 | 骨架屏用 1.2s 呼吸，不用位移动画 |
| 降级 | `@media (prefers-reduced-motion: reduce)` → 全部 `animation: none; transition: none`（**含骨架屏**） |

## 六、可达性硬约束（WCAG）

1. 所有可交互元素具备 hover / active / focus-visible 三态，`focus-visible` 用
   `outline: 2px solid` + `outline-offset: 2px`，**不得**用 `outline: none` 代替。
   **输入框例外**（第 1 轮评审后补写）：输入类控件用 `outline-offset: -1px` 贴住边框，
   因为外扩 2px 会与相邻控件重叠；捕获框这类「整块是输入区」的容器，
   焦点由外层 `:focus-within` 表达（整块边框变深），内层给一层极浅底色。
   这个例外只适用于 `input` / `textarea` / `select` 与其容器，**不适用于按钮**。

2. 正文与背景对比度 ≥ 4.5:1；本产品正文绝不用 `label-secondary`。
3. 状态不能只靠颜色表达：琥珀「待确认」必须同时有文字标签。
4. 表格化列表使用 `role="list"` / `role="listitem"`，不用 `div` 假装。
5. 浮层焦点管理：打开时焦点移入、`Esc` 关闭、关闭后焦点回到触发元素。

## 八、禁止清单之外，本方向卡自己加的三条禁令

1. **禁止在条目行里放 4 个以上按钮**。现状 `memory.ts` 详情页有 5 个并列出口按钮
   （编辑源码 / 确认 / 驳回 / 再留 90 天 / 归档），用户无法判断哪个是主操作。
   v4 规则：一行最多 1 个主按钮 + 1 个文字链接，其余进「更多」。
2. **禁止把流程术语直接当界面标签**。「该补了」「爬升」「减重」「锚点校验」是内部术语，
   界面上必须换成用户语言（见 IA 文档的术语对照表）。
3. **禁止在首屏出现用户无法行动的数字**。任何指标必须能回答「所以我现在该点哪里」；
   回答不了的（如分母为 0 的命中率）降级到「库健康」页，不出现在首屏。

   **裁决（第 2 轮评审补写：原文缺这条的具体判定）**：
   「每请求成本 171 tokens」出现在「今天」页的线索行里——它是**成本数字**，
