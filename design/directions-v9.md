## 零、范围硬事实（先定死，再谈方向）

**4 个表面 × 真实宽度**（这不是假设，是宿主扩展点决定的）：

| # | 表面 | 宽度 | 一句话任务 | 能否野外变形 |
|---|---|---|---|---|
| S1 | 侧栏记忆面板 | **400px**（实测） | 主工作区，5 分区全在此 | 否，宽度由宿主侧栏决定 |
| S2 | 会话记忆 tab | 宽（随会话栏，≥640） | 回答「这次会话注入了什么、为什么」 | 可加列 |
| S3 | 右侧栏快速捕获 | **≤320px** | 只做「记一条」，单行速记 | 否，最窄 |
| S4 | `/remember` 浮层 | 520–640px 居中 | 单条捕获 + 隐私拦截 + 撤销 | 可写宽 |

**5 个分区**（`pane-nav.ts:37`，v4 起任务导向）：今天 / 记一条 / 待办 / 记忆 / 库健康。
**新增 3 视图**：V1 常驻前缀四桶明细（R1–R9）· V2 置顶编辑（R10–R16）· V3 版本与差异（R17–R24），全部落在 `health` 内。

**因此「全产品方向」必须同时回答三件事**：一套语言怎么在 400 / ≥640 / ≤320 三个宽度里不塌；
5 个分区怎么不被排成 5 个平级抽屉；V1/V2/V3 这种「条目级 + 可编辑 + 状态机」的内容怎么住进来。

**共同硬约束**（不豁免）：只用宿主 `--dsw-alias-*`；无 Emoji 结构图标；无 `hover:scale`／滚动 fade-up／渐变字；
无「border+radius+padding」三者同在的分组容器（浮层与输入控件除外）；每页唯一 T0 且只给数字；
四态分离（`error ≠ empty ≠ 0`）；状态不只靠颜色。

## 二、六个方向

### D1 · 同一张纸（One Sheet）

**一句话概念**：全产品只有一张纸——读头 + 单栏清单，四种尺寸只是这张纸被裁窄或加列。

- **布局策略**：5 分区共用同一骨架（三行读头 / 左缘序号 / 零圆角行 / 行下元信息）；
  S1 单栏；S2 同栅格加一列（正文 1fr + 证据列 240px）；S3 裁到只剩输入 + 最近 3 行；S4 居中 560 宽浮层。
  V1–V3 也走这张纸：四桶=折叠段，编辑=整页替换，版本=末段。
- **视觉关键词**：1px 规则线／序号列／2px 刻度／T0 40 只给数字／零圆角／墨块主操作／无卡片。
- **适用理由**：迁移成本最低，v8 已在 S1 实测过（`headH≤155`、`paperOverflow=0`、机检双 0）；
  同一骨架上加列是唯一能在 320→640 之间不写两套 CSS 的做法。
- **代价**：全产品长得像「同一个列表的五份拷贝」，5 个分区之间缺少**结构性差异**，用户靠读标题区分；
  V1 的四桶 40+ 条条目在单栏纸面上必须滚动，首屏答不了「哪条贵」。

### D2 · 双车道（Push / Pull）

**一句话概念**：产品最独特的事实是记忆有两条通道——每请求都在的（推送）与命中才读的（拉取），界面就该有两条车道。

- **布局策略**：每个分区的纸面被一条**通道分割线**切成上下两带：上带「每请求都在」= 置顶规则 + 常驻四桶；
  下带「命中才读」= 索引 / 条目 / 未命中。5 个分区的差别只在**下带内容**，上带恒定可见（可折起 1 行）。
  跨表面：S2 用它回答「这次注入了什么」（上带=注入），S3 只保留下带入口，S4 不动车道。
- **视觉关键词**：双带／分割线（l2）／上带窄（≤72px）下带宽／等宽成本角标／蓝色只做「已推送」标记／无圆角。
- **适用理由**：把 §21 的「推送 vs 拉取」变成可见结构，直接回答新需求的核心问题「关掉哪条能省多少」；
  这是 6 个方向里唯一从**产品模型**（而非排版）长出来的脊柱，原创性最高。
- **代价**：上带占了 400px 每页顶部 72px，等于五页都交一份「常驻税」；概念较重，新用户不知道「推送/拉取」是什么，
  必须靠文案解释（术语不能上界面，v8 §八-6 已禁）。

### D3 · 流水线（Pipeline）

**一句话概念**：5 个分区不是 5 个平级页，是同一根管的五个阶段——捕获 → 流转 → 拍板 → 落档 → 退役。

- **布局策略**：纸面顶部一条 5 段进度轨（每段带计数），下面是**当前阶段**的清单；点别的段=切分区；
  分区导航因此可以下沉到这条轨里（省掉一行导航）。跨表面：S3 只显示「捕获」一段，S4 是捕获的确认页，
  S2 显示「本次会话从管里取了哪几段」。V1/V2/V3 挂在「退役/维护」段下面。
- **视觉关键词**：段轨／计数角标／当前段 2px 下划线／箭头连接／零圆角／等宽计数。
- **适用理由**：正面治「单向漏斗」（`docs/product.md` §5.2：记了 8 条、0 条拍板）——界面本身显示「你有 8 条卡在流转」；
  也是唯一把「今天/待办」两页重复感消除掉的方向。
- **代价**：流水线隐喻要求每页只有一个合法下一跳，而产品实际允许乱序（在记忆页直接改状态）；
  段轨在 400px 里要压到 5×72px，中文标签两字一断，容易读成药丸轨道（v7 已判死的形态）。

### D4 · 账本双面（Ledger ⇄ Register）

**一句话概念**：同一份记忆，一面看钱（每条占多少每请求成本），一面看内容（这条写了什么），一个开关翻面。

- **布局策略**：全产品顶部一个双态开关（`看内容 / 看成本`），切换同一份清单的列集：
  内容面=标题+摘要；成本面=名称+来源+tokens+计费+占比，行高不变。5 分区各自有默认面（今天=内容，库健康=成本）。
  V1 的四桶是「成本面」的自然延伸；V2 编辑在两面里都可就地进入；V3 是成本面的附录。
- **视觉关键词**：双态开关（不是 tab）／同一行两种列集／右对齐等宽数字／账本线（l1）／无圆角／蓝只做开关态。
- **适用理由**：主张 1「成本可见」不必独占一个分区——让它成为**所有分区的第二个视角**，成本才有决策价值；
  R1（顶栏=四桶和）在成本面里天然成立。
- **代价**：两面列集不同会让「我刚看的那条去哪了」反复发生；开关态是全局状态，跨表面同步（S2 是否跟随）需要规则；
  实现上等于每个分区写两套行渲染。

### D5 · 体检报告（Verdict First）

**一句话概念**：每页开头先给判定——「2 条该拍板 / 1 个问题没被记住 / 0 条该退役」，清单只是证据。

- **布局策略**：纸面首屏是一句判定（T3 单行、≤20 字）+ 一个动作；清单按「该不该动」排序，行首是结论词，
  行尾才是数字。5 分区的判定各不相同；V1 的判定是「229 里 71 是你能关的」，V3 的判定是「落后 3 个版本，改动 7 条」。
  跨表面：S2 的判定=「本次注入 3 条，2 条被引用」；S3 无判定（只捕获）。
- **视觉关键词**：结论句在前／2px 色条只编码可动·不可动／数字在行尾／箭头动作／状态词必在文字里／少用蓝。
- **适用理由**：产品主张是「人负责拍板」，界面就该以判定而非数据开场；也直接兑现 PRD §1.2「从看到到改完 ≤3 次点击」。
- **代价**：判定要先算（前端算或后端给），算不出的项必须显式说「算不出」而不是给 0——四态压力最大；
  清单退居证据位后，用户想核对合计时会觉得「账被藏了」。

### D6 · 工作台（Workbench，桌面优先）

**一句话概念**：承认这是存量桌面端产品——左侧 212px 分区轨 + 右侧内容区 + 分区卡片，窄屏降级为抽屉。

- **布局策略**：≥1024：双栏 + 卡片分区（PRD 原型那条路）；400–1023：轨变顶部分段；≤400：
  侧栏面板里退化成 D1 的单栏 + 抽屉。V1 的四桶正好用 4 个 KPI 卡 + 构成条 + 明细表（PRD 原型现状）。
- **视觉关键词**：212px 轨／10px 圆角卡片／4 格 KPI／构成条（stacked bar）／表格／浅灰底 `#f7f8fa`。
- **适用理由**：V1 的「四桶+合计+占比」在宽屏里用卡片与构成条确实比 400px 单栏好读；
  若产品确定要做独立 Web 管理端（`packages/memory-web`，目前**不存在**），这是唯一对得上的方向。
- **代价**：**与 v8 誓约正面冲突**（卡片墙、10px 圆角、灰底），且 400px 里卡片墙会被压成一叠空框；
  PRD 已明确「不新增一级分区」「不新增第五表面」，此方向实际上是在改产品形态，不只是改视觉。

| | 400px 不塌 | 320px 捕获 | 宽 tab 加列 | 5 页有结构差异 | V1 四桶 | V2 编辑 | V3 版本 | 迁移成本 | 与 v8 |

| D1 同一张纸 | 高 | 高 | 高 | **低** | 中（要滚） | 高 | 高 | **低** | 延续 |
| D2 双车道 | 高 | 中 | 高 | 高 | 高（上带即四桶） | 中 | 中 | 中 | 换脊柱 |
| D3 流水线 | 中（轨易成药丸） | 高 | 中 | 高 | 低 | 中 | 中 | 高 | 换脊柱 |
| D4 账本双面 | 高 | 低（开关无处放） | 高 | 高 | 高 | 高 | 高 | 高 | 换脊柱 |
| D5 体检报告 | 高 | 高 | 高 | 中 | 中（缺核对） | 高 | 高 | 中 | 换重心 |
| D6 工作台 | **低** | 低 | 高 | 高 | 高 | 高 | 高 | 高 | **冲突** |

**主代理倾向（供参考，不是决定）**：**D1 做骨架 + D2 做脊柱 + D5 做开场**——
400px 这张纸保住（迁移成本与实测数据都在），把「推送/拉取」双带作为五页共有的可见结构（它是产品独有的、也是新需求的问题所在），
每页首屏用一句判定开场（兑现有「拍板」主张）。D4 的双面开关可作为 `记忆` 页的单页增强，不进全局。
D3 的段轨与 D6 的卡片墙建议**不进本轮**：前者易退化成 v7 已判死的药丸轨道，后者与 400px 事实冲突。
