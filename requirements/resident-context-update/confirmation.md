## 一、我自行补充的规则（你没说，我按经验定的）

| # | 我补的规则 | 关联 | 为什么这么定 | 你若不同意，改法 |
|---|---|---|---|---|
| A1 | 常驻前缀加**第四桶 `toolschema`**（本插件两个工具的 description + 参数 schema） | R1 / R7 | 这两个工具每请求都在上下文里；不算进去顶栏就低于真实付费量，正是 `product.md` §12 骂过的"口径不一致" | 改回三桶，但必须在面板上写"不含工具 schema" |
| A2 | **总预算 1024 与段落预算 256 分层呈现**（顶栏画总预算轨，置顶桶内画 256 子预算） | R1 / R5 | 同屏出现 1024 与 256 却没解释，用户会认为系统算错 | 只保留 256，把 1024 标为"历史定义" |
| A3 | **单条置顶上限 64 tokens** | R14 | 注入段每条只渲染 `- [id] 标题`，64 tokens 约等于 2 行标题，够用且留余量 | 给具体数，或改成"只警告不设数" |
| A4 | 置顶条目在编辑视图里**只允许改标题**（注入的就是 id + 标题） | R10 | 正文不进入常驻，改正文对成本零影响，不该混进"常驻编辑" | 允许标题 + 正文一起改（但正文编辑仍在记忆详情更顺手） |
| A5 | 段落包装（`## 记忆库置顶规则` / 结语）**开放编辑 + 可恢复默认** | R10 / R15 | 它是常驻文本的一部分，且是插件自有文案；dsh-memj 的做法证明可行 | 锁死只读，理由是"措辞固定避免作废缓存" |
| A6 | 取消置顶 = **`pinned: false`，不删条目** | R15 | 删条目是另一件事（要人拍板），混在一起会让"关掉成本"变得危险 | 取消置顶同时归档（不推荐） |
| A7 | **注入段去掉运行时数字**（`另有 N 条…超出 256` 改为固定文案） | R5 / 见冲突 C2 | 该文本在系统提示词里；N 一变就破前缀缓存（本仓实测单次 20–57 万 tokens）| 保留数字，但接受"每次库变化作废一次缓存" |
| A8 | "被跳过的置顶条目"改为**只在 UI 显示**（明细行带"跳过 · 超段落预算"） | R5 | 信息不丢，只是从提示词搬到界面 | 维持现状 |
| A9 | 技能 description **仅当 SKILL.md 在受管目录时可编辑**，否则只读 + 原因 | R10 | 插件无权改别人的仓；写错一处会污染 agent 行为 | 全部只读（最保守） |
| A10 | 更新检查的来源固定为**两个**：`tags` 与 `HEAD commits`，并显示"已检查 2 个来源" | R19 | 只查 tags 会在"没发版"时误判已最新；只查 HEAD 会丢掉正式版本信息 | 只查 tags |
| A11 | 更新入口优先级改为**宿主版本区块 → 复制命令 → 市场 API**（宿主能做就交给宿主） | R21 | 截图证据：宿主插件页已渲染"可更新到 0.86.0 · 发布于 / 1 个新版本 / 重新检查"，并内置热更新与失败回滚；我们重造一遍只会多一套回滚状态要维护 | 仍自建三路径 |
| A12 | `link` 安装（本地源码）**禁止更新**，只给 `pnpm build` 指引 | R22 | 覆盖用户正在改的代码是不可逆操作 | 允许更新但先备份（不推荐） |
| A13 | 版本差异只展示**当前→目标**区间，不做全量历史 | R18 | 全量历史对"这次升不升"的决策没有增量价值 | 加"查看全部提交"链接 |
| A14 | 更新成功后**不自动刷新**，给"刷新页面"按钮 | R22 | 自动刷新会打断正在进行的会话；重启更该由人决定 | 自动刷新（不推荐） |
| A15 | 在 PRD 里新增一条产品主张：「**常驻内容必须可审可改，不可改的要给理由**」 | §1.3 | 三条需求共同指向同一条原则；不写下来下次又会退回"只读面板" | 不写成主张，只当功能 |
| A16 | **编辑路由只接受本机回环**，非回环 → 403（不是"失败红条"） | R16 | 编辑是唯一会写用户文件的入口，必须与现有 bridge 围栏同一条线；跨机器写入无法审计 | 放开到同网段（不推荐） |
| A17 | 保存回执必须含**改动行数**（"第 12 行 1 行变化"） | R13 | A10 要求用 `git diff` 对账；只给路径无法核对"是不是只改了一行" | 回执只给路径 |
| A18 | 更新前用目标版本的 `engines.dsh` **拦截不兼容**，并给可装范围 | R20 | 版本错配不是"升级失败"，而是整个 web shell 起不来（`dsh-context-doctor` #9 的原话）；必须前置 | 只警告不拦 |
| A19 | **发布 npm 包**，作为 3.3 的前置（**打 git tag 无效**） | R17 / R21 | **已实测**：宿主 `listVersions()` 对 `kind === 'git'` 直接返回 `not-updatable`（查 registry 之前就返回），理由 `installed from Git, which lists no versions`；`parseInstallSpec()` 对 `#path:…&v0.2.0` 仍判 `git`。所以 tag 不是选项，只有 registry 源才行 | 接受永远 `not-updatable`（只能命令升级） |
| A20 | **我方不实现更新执行**（不下载/不装包/不回滚），只展示与引导 | R22 / R24 | 两个入口同时存在时，回滚状态会分叉（谁回滚、回到哪一版无法判断）；单一入口是唯一能保证"回滚语义确定"的做法 | 自建执行 + 自己回滚 |
