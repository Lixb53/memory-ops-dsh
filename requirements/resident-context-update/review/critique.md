## 四、后续修正：新证据推翻 3.3 的原方案（2026-11-21，**不是复审**）

用户提供了宿主插件页的真实截图（dsh-context 卡片底部「版本」区块：

- `可更新到 0.86.0 · 发布于 2026-11-19`

## 五、实测结果（2026-11-21，补上 §四 留的那一条）

用宿主自己的实现验证（详见 `../research/host-version-block-verification.md`）：

| 安装源 | 宿主归类 | 版本区块 |
|---|---|---|
| `github:…#path:packages/dsh-plugin&<commit>` | `git` | **refused / not-updatable**（`installed from Git, which lists no versions`），**不查 registry** |
| `github:…#path:…&v0.2.0`（打 tag） | `git` | 同上——**tag 救不了** |
| `link:…` / 本地路径 | `path` | 无版本可比 |
| `dsh-context@0.85.1` | `registry` | 可列出「可更新到 + 发布日期 + N 个新版本」 |

据此把 R22 从三态扩成四态（新增 `not-updatable`），并把「发 npm」从"备选"升级为**唯一出路**（确认单 A19 已改）。
另外发现宿主会把 `not-updatable` 渲染成"失败（其它）"+ 英文原因——所以我们在 R22 里要求**翻译成人话**，
不把宿主那句英文当失败抛给用户。
