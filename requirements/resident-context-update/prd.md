## 一、需求概述

### 1.1 三句话

用户装了记忆库插件，但有三件事说不清、做不到：

1. **说不清**："常驻前缀 229 tokens"——**这 229 是哪几段、各多少、关掉哪条能省多少**？（需求 3.1）
2. **做不到**：看到了成本，**却没有地方就地查看/修改这些常驻内容**，只能去别的分区翻源码。（需求 3.2）
3. **看不到"改了什么"**：宿主插件页已能给"可更新到 0.86.0 · 发布于 2026-11-19"，但**不给提交清单**；
   升级动作本身宿主已能做（含热更新与失败回滚）。我们缺的是那一页"改了什么"。（需求 3.3）

### 1.2 成功判据（可检查）

| 判据 | 目标 |
|---|---|
| 从总览点进「常驻前缀」，能回答"哪几条、各多少 tokens" | 100% 条目可见，桶内条目之和 = 桶数字 |
| 从看到某条置顶到改完保存 | ≤ 3 次点击 + 1 次保存；保存前可见 token Δ 与生效时机 |
| 从打开「版本」到看清"改了什么" | 差异逐条可核验（commit/发布说明），无"若干改进"式描述 |
| 升级路径 | 不需要手动卸载；且必须标明"要不要重启/刷新" |

### 1.3 与既有产品主张的关系

- 与「成本可见」（`docs/product.md` §三 主张 1）同向：本次是把**桶级可见**推进到**条目级可见**。
- 与「置顶注入是唯一由你直接控制大小的每请求成本」（`docs/product.md` §21.6）同向：
  只有逐条可见，"关掉一条能省多少"才第一次成为可回答的问题。
- **新增一条主张**（需确认）：「常驻内容必须可审可改，不可改的要说明理由」。

### 2.2 不做（本期明确拒绝，避免范围漂移）

| 不做 | 理由 |
|---|---|
| 不自动改 skill 文件（SKILL.md 若不在受管目录则只读） | 尊重"文件在谁手里谁负责"，避免插件越界改别人的仓 |
| 不做"写回源码"（把 UI 覆盖固化进插件源码） | 插件运行期没有源码写权限；做了也只能写副本，等于制造第二真相源 |
| 不做全量上下文审计（工具 schema 的重复/遮蔽检测、MCP 面） | 那是 `dsh-context-doctor` 的活；本产品只做"与记忆库相关的常驻成本"（catalog/frame/injected/本插件两个工具） |
| 不做自动更新（后台静默升级） | 与"只追加、可审"冲突；且宿主重启代价高（`docs/product.md` §17.1 同一理由） |
| 不做版本选择器 / 冻结版本（BRAT 式） | 本期只到"最新 tag/HEAD"，多版本管理留待 V2 |
| 不改工作域置顶的注入策略（默认 false 不变） | 现有理由成立（跨分支串味），不在本次范围 |

## 三、功能需求

### 3.1 模块 A · 常驻前缀明细（视图 V1）

**数据口径（先定死，再谈界面）**

| 桶 | 内容 | 计费 | 是否可编辑 |
|---|---|---|---|
| `catalog` | 每个 skill 的 name + description | 每请求 | 视 skill 文件位置（R10） |
| `frame` | `<available_skills>` 目录框架（实测常量 171） | 每请求 | 只读（宿主生成） |
| `injected` | `pinned: true` 的个人域条目，逐条 `- [id] title` | 每请求 | 可编辑（写库） |
| `toolschema` | 本插件注册的两个工具（`memory_recall` / `memory_write`）的 description + 参数 schema | 每请求 | 只读（代码生成） |
| `index`（**不计入常驻**） | `layer: l0` 索引文件 | 按需（被 read 才付费） | 可编辑 |

- **R1** 常驻前缀的顶栏数字 **必须等于四桶之和**：`catalog + frame + injected + toolschema`。
  不允许出现"顶栏一个数、明细另一个数"（`docs/product.md` §17.4② 的老坑：KPI 曾把索引层冒充常驻）。
- **R2** 每个桶都可展开到**条目级**；每条至少含：名称、所属桶、来源（文件路径 / `宿主内置` / 条目标识 / `代码生成`）、
  tokens、占比、计费性质（每请求 / 按需）。
- **R3** 每个 token 数字旁必须可获取**估算口径声明**："CJK 1 字≈1 token、其余 4 字符≈1 token；
  非 tokenizer 精确值，仅用于相对比较"。悬停或统一脚注皆可，但不得省略。
- **R4** 桶内条目 tokens 之和 **必须等于**该桶数字；不等时显示差额并在条目区顶部写明原因
  （`未计入：宿主未暴露` / `截断：超 500 字符描述按宿主规则截断`）。
- **R5** 置顶桶必须**逐条**列出：`id`、标题、tokens、**是否实际注入**（真/否）、未注入原因（`超 256 tokens 段落预算`）。
  当期 `read.ts` 把整桶聚合成 `injected.pinned` 一条，本次必须拆开。
- **R6** 三态分离：`ok`（有数据）/ `empty`（确实一条都没有）/ `error`（读不到，必须带原因串）。
  **禁止**把 `error` 或"还没检查"渲染成 `empty` 或 `0`（`docs/product.md` §18.5 教训 1）。
- **R7** 工具 schema 桶若宿主未暴露 schema：显示 `不可读` + 原因，**不显示 0**，且合计行必须写明
  "合计不含工具 schema（当前不可读）"——否则用户会以为已算全。
- **R8** 只读项必须标 `只读` 与理由（"宿主生成，插件无权改"）；可编辑项必须给"去编辑"的入口（跳 V2）。
- **R9** 计费性质必须可区分：索引层条目保留 `billed: false` 并单列，不与常驻桶混排（沿用 `read.ts:269/300` 的 `billed` 字段）。

### 3.2 模块 B · 常驻前缀编辑（视图 V2）

**可编辑对象模型**（对齐 Letta memory block 的 `label/description/value/limit/read_only`）

```
EditableTarget {
  id            // 稳定标识：pinned:<entryId> / wrapper:header / wrapper:footer / skill:<name>
  kind          // pinned | wrapper | skill-description | readonly
  source        // 文件路径（pinned/ skill）/ 'memory-ops 配置'（wrapper）/ '宿主'（readonly）
  value         // 当前文本
  tokens        // 当前 token 估算
  limit         // 上限（pinned 单条 64；wrapper 整段不超 32；skill description 500 字符）
  readOnly      // bool
  readOnlyReason
  effect        // 'new-session'（置顶/包装）/ 'reload' / 'restart'
}
```

- **R10** 四类对象逐项标注可编辑性，且不可编辑项必须说明原因：
  | 对象 | 可编辑 | 原因/条件 |
  |---|---|---|
  | 置顶条目（`pinned: true` 的标题） | ✅ | 写回 `~/.memory-ops/**/<file>.md` 的 frontmatter `title` 或正文首行 |
  | 段落包装（`## 记忆库置顶规则` / 结语） | ✅ | 存在插件配置，可恢复默认 |
  | 技能 description | ⚠️ 条件 | 仅当 SKILL.md 位于 `~/.dsh/skills/` 等受管目录；否则只读 |
  | 目录框架 / 工具 schema | ❌ | 宿主与代码生成 |
- **R11** 保存前必须给出**变更预览**：`diff（前/后）` + `tokens 前 / 后 / Δ` + `生效时机`。三项缺一不可保存。
- **R12** 生效时机必须显式写在保存按钮旁：
  - 置顶条目 / 包装 → `新会话生效；当前会话保持原样（按会话冻结，避免作废 KV cache）`；
  - 禁止写"立即生效"这种做不到的承诺。
- **R13** 保存写回文件：原子写（tmp + rename）、只改目标字段、成功后回执含**实际文件路径**与"改了几行"。
- **R14** 校验（拒/警分开）：
  | 情况 | 行为 |
  |---|---|
  | 标题为空 / 全空白 | **拒**，说明"空标题会让模型拿到一条无意义规则" |
  | 单条 > 64 tokens | 警告（可保存），提示"超预算条目会被跳过，等于没注入" |
  | 置顶合计 > 256 tokens | 警告（可保存），提示"新会话会跳过靠后的条目，顺序即优先级" |
  | 隐私闸门命中（密钥/身份证/内网 IP） | **拒**，给"填入脱敏文本"按钮（沿用 `privacy.ts`） |
  | 含 `{{` | 允许保存，提示"不会做变量插值（`interpolate:false`），原文照发" |
  | **拒与警同时命中** | **互不短路**：任一"拒"级命中即禁用保存；警告不得因为先命中而跳过"拒"的判定（实现须独立判定后汇总） |
- **R15** 逆操作：`取消置顶`（置 `pinned: false`，条目本身保留）、`恢复包装默认`。
  **不提供**"写回源码"，并写明原因（插件无源码写权限，会制造第二真相源）。
- **R16** 编辑入口仅接受本机回环请求；保存需二次确认；成功/失败都出结果条（失败带宿主原文），
  禁止裸 `void call(...)`（`docs/product.md` §18.2 教训 2）。

### 3.3 模块 C · 版本与更新（视图 V3）

- **R17** 版本页必须显示五项：`当前版本`（插件 `package.json` 的 `version`）、
  `代码来源`（依赖 spec，如 `dsh-context@0.85.1` 形态）、`安装方式`（`npm` / `git` / `link` / `unknown`）、
  `当前提交`（短 sha，7 位；npm 安装可缺省）、`目标`（宿主给出的"可更新到 X + 发布日期"）。
  **证据**：宿主插件页已渲染这组数据（截图：`当前版本 0.85.1` / `代码来源 dsh-context@0.85.1` /
  `可更新到 0.86.0 · 发布于 2026-11-19`）；能读到宿主结果时**直接复用，不重复自建检查**（见 R24）。
  **git / link 安装时**「目标」显示"宿主不列出版本（安装源非 registry）"——不得显示 `—` 冒充"未检查"
  （依据：`research/host-version-block-verification.md` §三）。
- **R18** 差异清单是**我们唯一不可替代的增量**（宿主管版本与发布日期，不管"改了什么"）：
  每条 = `短 sha · 标题 · 日期`，或发布说明标题 + 链接。
  **禁止**出现"若干改进""可能包含性能优化"这类无法验证的描述。
  **未检查 / 检查失败 / 超时时不展示差异清单**，只显示一条说明——否则"没查到"会被读成"没有更新"。
- **R19** 检查更新三态，且必须标明**结果来源**（`宿主` / `自建`）：
  | 态 | 文案要求 |
  |---|---|
  | 已最新 | 必须同时显示"已检查 N 个来源 / 时刻"（`checked` 与 `updatable` 分开） |
  | 有更新 | 显示当前→目标（含发布日期，若宿主给）+ 差异条数 |
  | 检查失败 | **显示原因**（网络不可达 / 代理未生效 / 仓库 404 / 无权限 / **超时（N 秒无响应）**）+ 重试按钮；**不得显示为已最新** |
  | 未检查 | 目标与差异显示 `—（未检查）`，不得预填"最新 tag / 3 条差异" |
- **R20** 兼容性前置检查：用目标版本的 `dsh.engines.dsh` 与本机宿主版本比对；
  不满足 → 禁用一键更新，显示"目标要求 DSH `>=x`，当前 `y`"，并给可回退的版本建议。
- **R21** 更新入口按**宿主优先**排序，每条都标"谁执行 / 要不要重启"：
  | 序 | 入口 | 前提 | 谁执行 | 我们做什么 |
  |---|---|---|---|---|
  | 1 | **宿主插件页「版本」区块** | **安装源是 registry（npm）** + 宿主给出版本区块（截图已证：`可更新到 0.86.0 · 发布于 2026-11-19` / `1 个新版本` / `重新检查`） | **宿主**（含热更新、失败回滚旧版本） | 展示其"可更新到 / 发布日期 / N 个新版本"，给"去宿主页更新" |
  | 2 | 复制命令 | 总是可用（headless / 旧宿主 / git 直装） | 用户 | 生成带 `@<ref>` 的命令，标"需重启" |
  | 3 | 市场 update API v1 | 装了 `dshmarket` 且要批量操作多插件 | 市场 | 只探测与跳转，不自建 |

  **不可用的入口不渲染**；**任何界面不出现两个"执行更新"的按钮**（见 R24）。
- **R22** 更新可用性三态——**我们不实现更新执行**（不下载、不装包、不回滚）：
  | 态 | 判定 | 界面 |
  |---|---|---|
  | `host-managed` | 宿主版本区块可用 | 主按钮"去宿主页更新"；文案写明"更新由宿主执行，热更新失败会自动回滚旧版本" |
  | `command-only` | 无宿主区块（headless / 旧宿主） | 只给命令 + "需重启" |
  | `blocked` | `link` 安装 / `engines.dsh` 不满足 | `link` → "开发模式：`pnpm build` + 刷新，此处不提供更新"；版本不满足 → 禁用更新并给可装范围 |
  | `not-updatable` | 安装源是 `git`（宿主明确返回 `not-updatable`，理由 "installed from Git, which lists no versions"） | 显示**人话**"git 安装无法比较版本" + 命令兜底；**不得把宿主那句英文原因原样当"失败"抛给用户**（依据：实测报告 §三） |
- **R23** 更新只改插件代码，**不动 `~/.memory-ops/`**；若目标版本声明需要数据迁移，
  必须在更新前弹确认并显示备份命令（`cp -r ~/.memory-ops ~/.memory-ops.bak`）。
- **R24** **单一入口原则**：同一插件在任何界面上**最多一个"执行更新"的动作**。
  宿主能做就交给宿主（我们只展示结果与引导）；若宿主将来开放 update API 给插件，也只调用它，
  不自建下载 / 安装 / 回滚。理由：两个入口同时存在时，回滚状态会分叉（谁回滚、回到哪一版无法判断）。

## 四、验收要点（逐条回指规则）

| # | 验收项（可检查） | 回指 |
|---|---|---|
| A1 | 顶栏「常驻前缀」数字 = 四桶之和；构造"桶内多算 1 token"的假数据，界面必须显示差额而不是静默取整 | R1 / R4 |
| A2 | 展开四个桶，每条都能看到名称、来源、tokens、占比、计费性质；条目数 > 0 时不得显示"暂无条目" | R2 |
| A3 | 任一 token 数字可触达"估算口径"说明（悬停或脚注）；说明文本含 `CJK` 与 `4 字符` | R3 |
| A4 | 置顶桶展开后条目数 = 库里 `pinned: true` 的个人域条目数；每条带"注入 / 跳过 + 原因" | R5 |
| A5 | 把 skill 读取改造成抛错：界面显示 `error` + 原因串，**不显示 0 或空态** | R6 |
| A6 | 隐藏工具 schema 后：该桶显示"不可读 + 原因"，合计行写"不含工具 schema" | R7 |
| A7 | 只读项带 `只读` 徽标与理由；点击"编辑"只出现在可编辑项上 | R8 |
| A8 | 索引层条目带"按需"标记且不计入常驻总数（`billed=false`） | R9 |
| A9 | 编辑置顶标题，保存前可见 diff + `tokens 前/后/Δ` + "新会话生效" | R11 / R12 |
| A10 | 保存后回执含文件路径；文件内容用 `git diff` 核对，只改了目标标题（无 frontmatter 其它字段变化） | R13 |
| A11 | 空标题保存被拒且给理由；超 64 tokens 是警告不是拒；含密钥的文本被拒并给脱敏按钮 | R14 |

## 附三 · 状态表

| 区域 | 状态 | 判定 | 界面要求 |
|---|---|---|---|
